Understanding keyTimes and keySplines in SMIL Animation

Synchronized Multimedia Integration Language (SMIL) allows developers to animate SVG elements directly within markup, providing precise control over motion and transitions. This article explains how the keyTimes and keySplines attributes work together to dictate the pacing and velocity of an animation, transforming rigid, linear state changes into fluid, natural movements using custom timing intervals and Bézier curves.

The Role of Pacing in SMIL

By default, SMIL animations interpolate between values at a constant speed using linear pacing. While functional, linear pacing often feels mechanical. Realistic motion requires variable pacing—acceleration, deceleration, and momentary pauses. SMIL controls this behavior using the calcMode attribute alongside keyTimes and keySplines.

Understanding keyTimes

The keyTimes attribute controls when specific animation frames occur during the total duration. It is specified as a semicolon-separated list of floating-point values between 0 and 1, representing the proportional timeline of the animation.

  • Format and Rules: If an animation has four target values in its values attribute, keyTimes must also contain four values. The sequence must always begin with 0 (the start of the duration) and end with 1 (the end of the duration), with each intermediate value greater than or equal to the previous one.
  • Functionality: In an animation lasting 10 seconds, a keyTimes sequence of 0; 0.2; 0.8; 1 means the second keyframe is reached at 2 seconds (20%), the third keyframe is reached at 8 seconds (80%), and the final state is reached at 10 seconds. This allows you to stretch or compress specific phases of an animation.

Understanding keySplines

While keyTimes controls timeline markers, the keySplines attribute defines how the animation transitions between those markers. It controls acceleration and deceleration using cubic Bézier curves, identical to the cubic-bezier() timing function in CSS.

  • Format and Rules: The keySplines attribute only functions when calcMode="spline" is explicitly declared. It consists of a semicolon-separated list of cubic Bézier control points written as x1 y1 x2 y2.
  • Mapping: Because curves define the transitions between points, the number of Bézier definitions in keySplines must be one less than the number of entries in keyTimes. For \(N\) keyframes, there are \(N-1\) intervals.
  • Control Points: The values for x1 and x2 must fall between 0 and 1, representing the normalized time interval. The values for y1 and y2 represent the progress of the property and can fall outside the 0 to 1 range to create overshoot or bounce effects.

How keyTimes and keySplines Work Together

Together, keyTimes and keySplines separate temporal positioning from velocity control:

  1. keyTimes sets the temporal checkpoints: It defines the exact percentage of total duration allocated to each animation stage.
  2. keySplines defines the curvature: For each stage allocated by keyTimes, the associated Bézier spline defines whether the transition eases in, eases out, maintains constant speed, or snaps sharply.

For example, to create a smooth ease-in-out effect across two values:

<animate
  attributeName="cx"
  values="50; 450"
  dur="3s"
  calcMode="spline"
  keyTimes="0; 1"
  keySplines="0.42 0 0.58 1" />

In multi-step animations, combining these attributes allows developers to synchronize complex choreographies—such as an element accelerating quickly toward a midpoint, lingering, and then snapping to its final destination—entirely within declarative SVG markup.
