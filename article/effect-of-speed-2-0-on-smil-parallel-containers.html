Effect of speed="2.0" on SMIL Parallel Containers

Setting the speed="2.0" attribute on a SMIL parallel container (<par>) accelerates the container's internal timeline to twice the normal playback rate. This article provides a concise breakdown of how this attribute alters timeline progression, child element behavior, total duration, and temporal synchronization within the Synchronized Multimedia Integration Language (SMIL) framework.

Accelerated Timeline Mechanics

In SMIL, the speed attribute defines the playback rate of an element's local time coordinate system relative to its parent. A standard speed value of 1.0 represents normal time progression. When you set speed="2.0" on a <par> container, the container's internal clock advances two seconds for every one second that passes in the parent timeline.

Impact on Child Media Elements

Because the <par> container defines the time context for all of its enclosed children, the speed setting cascades downward:

  • Audio and Video Playback: Media elements such as <video> and <audio> render at double their normal playback speed, resulting in fast-forwarded video and high-speed audio, provided the media engine supports variable-speed playback.
  • Animations and Transitions: Timed elements like <animate> resolve their keyframes and interpolations in half the real-world time.
  • Implicit Durations: Any media element whose duration depends on its intrinsic timeline will end twice as fast in presentation time.

Resolution of Container Duration

The effective duration of the <par> element is inversely proportional to the speed value:

  • Simple Duration: If the container has an explicit duration defined (e.g., dur="10s"), the content will run for 10 seconds of internal time, which elapses in only 5 seconds of actual presentation (external) time.
  • Unspecified Duration: If the container's duration is determined by its longest child element (the default endsync="last" behavior), the overall active duration of the <par> container in real-world time is reduced by 50%.

Synchronization and Offsets

All internal timing offsets and synchronizations within the <par> container remain proportional to one another:

  • A child set to start at begin="4s" will begin after 2 seconds of real-world elapsed time.
  • Delays, intervals, and synchronization arcs between sibling elements within the container fire at twice the normal rate relative to external viewers, while their relative timing within the container remains intact.
