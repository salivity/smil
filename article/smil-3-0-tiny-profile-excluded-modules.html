SMIL 3.0 Tiny Profile Excluded Modules

The SMIL 3.0 Tiny profile is a lightweight specification engineered specifically for resource-constrained devices, such as low-power embedded systems and basic mobile hardware. To minimize memory footprint and processing overhead, the World Wide Web Consortium (W3C) stripped out several high-overhead modules found in larger SMIL 3.0 profiles. This article details the specific functional modules intentionally excluded from the SMIL 3.0 Tiny profile to ensure lean execution and low memory consumption.

Animation Modules

The entire SMIL Animation framework—including the BasicAnimation and SplineAnimation modules—is excluded from the Tiny profile. In full SMIL implementations, animation requires dynamic interpolation, frame-rate recalculations, and continuous memory buffering for attribute interpolation over time. Omitting these modules eliminates the continuous CPU cycles and rendering buffers required to interpolate vector paths, positions, and color values.

Transition Effects Modules

The BasicTransitions and TransitionModifiers modules are completely omitted. Transition effects, such as wipes, fades, and directional cross-fades, demand significant graphic memory because the rendering engine must retain both the outgoing and incoming visual frames simultaneously in memory to compute blending filters. Excluding transitions prevents visual buffer bloat and eliminates the need for dedicated compositing hardware.

smilText Modules

SMIL 3.0 introduced smilText, a module set designed for rich, in-band, timed text styling, layout, and motion text (such as karaoke or crawling tickers). The Tiny profile excludes all smilText modules. Supporting rich formatted text requires font-rendering engines, text-wrapping layout caches, and glyph storage, which impose a noticeable memory overhead. The Tiny profile instead relies on standard static external text or basic plain text references.

Advanced Timing and Synchronization Modules

While the Tiny profile retains core timing containers (<seq> and basic <par>), it eliminates several complex timing mechanisms:

  • ExclTimeContainers: The <excl> element, which defines mutual exclusion rules among media items, is excluded to avoid complex pause/resume state stacks.
  • SyncbaseTiming: Eliminates the tracking of dependencies where an element's begin or end depends dynamically on another element's schedule.
  • WallclockTiming: Removes dependencies on real-world calendar clocks and network time updates.
  • MediaMarkerTiming: Omits the ability to trigger timeline events based on internal cue markers inside media files, reducing parser complexity.

Extended Layout and Media Control Modules

The Tiny profile restricts visual placement strictly to the BasicLayout module, leaving out more demanding layout capabilities:

  • MultiWindowLayout: Excluded to prevent the window manager from allocating and maintaining multiple separate visual canvas surfaces.
  • AudioVolume and Panning Controls: Hardware-level panning and dynamic gain manipulation are left out to minimize audio processing buffers.
  • PrefetchControl: Explicit bandwidth throttling and proactive memory caching through <prefetch> are omitted, allowing the device's native network stack to manage buffers sequentially without custom application-layer cache managers.
