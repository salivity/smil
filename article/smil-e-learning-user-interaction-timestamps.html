SMIL E-Learning User Interaction Timestamps

This article explains the mechanism used to record user interaction timestamps within Synchronized Multimedia Integration Language (SMIL) e-learning modules. Because SMIL is a declarative, XML-based presentation language rather than an imperative programming language, capturing and storing temporal user data relies on SMIL’s internal event-timing model working in tandem with a host player environment and e-learning tracking standards such as SCORM or xAPI.

The Declarative Event Model

SMIL defines timing through declarative attributes such as begin, end, and dur. To handle interactions, elements are assigned event-based conditions rather than static time codes. For example, a target media node can specify begin="submitButton.click" or begin="choiceA.activateEvent".

When a user interacts with a designated UI element, the SMIL timing engine resolves the event dependency. While this handles branching and presentation synchronization internally, SMIL itself contains no native mechanism for writing persistent logs or analytics to a database.

Host Runtime and the SMIL DOM Bridge

To record an actual timestamp, the SMIL implementation exposes its presentation state to a runtime host—typically a web browser using a JavaScript engine, an EPUB reading system, or a dedicated media player.

  1. Event Interception: When a user initiates an interaction (e.g., clicking a button or completing an interactive segment), the host runtime captures the DOM event triggered by the SMIL element.
  2. Clock Resolution: The runtime evaluates two distinct timestamps:
    • Presentation Time (SMIL Clock): Retreived via SMIL DOM methods such as getCurrentTime(), this represents the elapsed position relative to the media timeline or active synchronization container (<par> or <seq>).
    • Wall-Clock Time: Generated by the system clock (typically in UTC/ISO 8601 format) to capture the real-world date and time the action occurred.

Data Mapping to E-Learning Standards

Once the runtime captures the interaction and its corresponding time values, it formats and serializes the data into standard e-learning tracking structures:

  • SCORM 2004: The runtime maps the interaction to the cmi.interactions.n data model. The wall-clock time is stored in cmi.interactions.n.timestamp, while the presentation duration or latency is recorded in cmi.interactions.n.latency.
  • Experience API (xAPI): The host constructs a statement containing an actor, verb, and object. The wall-clock time is set within the root timestamp property, while presentation-specific timecodes are recorded inside the statement's context or result.extensions object.

Through this bridge between SMIL’s internal timing events and the host runtime’s API, e-learning platforms successfully record accurate, synchronized interaction timestamps.
