How SMIL Calculates Active Time Intervals

This article explains how the Synchronized Multimedia Integration Language (SMIL) Timing and Synchronization model uses its Interval Tier to process begin and end instance lists into discrete, active time intervals. It details the step-by-step resolution algorithm, the interaction between instance lists and runtime constraints such as dur and restart, and how dynamic timing changes update the active presentation timeline.

The SMIL Two-Tier Timing Model

SMIL separates timing logic into two layers: the Instance Tier and the Interval Tier. The Instance Tier manages unresolved and resolved time points (derived from offsets, syncbases, wallclock values, or user events) within distinct begin and end lists. The Interval Tier processes these lists to compute a sequence of continuous, non-overlapping active intervals during which an element actually renders or executes.

Step 1: Sorting and Evaluating Instance Lists

Before constructing an interval, the Interval Tier sorts both the begin and end instance lists in chronological order.

  • Begin List: Contains candidate start times (\(B_0, B_1, \dots, B_n\)).
  • End List: Contains candidate termination times (\(E_0, E_1, \dots, E_n\)).

These lists can contain fixed numerical values (such as 5s), dependent syncbase values (such as prevElement.end), or dynamic times generated during playback (such as click).

Step 2: Selecting the Initial Begin Time

The engine scans the sorted begin list to select the earliest valid begin time (\(B\)):

  1. Current Time Evaluation: If calculating the initial interval, \(B\) must be the earliest instance that is greater than or equal to the document or parent container's start time (often \(t = 0\)).
  2. Post-Interval Evaluation: If computing a subsequent interval, \(B\) must fall strictly after the end of the preceding interval, unless the restart condition dictates an earlier cutoff.

If no valid begin instance is found, no interval is created, and the element remains inactive.

Step 3: Determining the Corresponding End Time

Once a valid begin time \(B\) is established, the Interval Tier searches the end list for an appropriate termination point (\(E\)):

  1. Condition \(E > B\): The engine searches for the earliest end instance in the list that is strictly greater than the selected \(B\). Any end instance where \(E \le B\) is ignored for this specific interval.
  2. Handling dur (Duration): If a dur attribute is present, it defines an implicit end constraint at \(B + \text{dur}\).
  3. Comparing dur with the End List: The provisional end time is defined as the minimum of the explicit end instance and the implicit duration: \[\text{Provisional End} = \min(E, B + \text{dur})\]
  4. No Explicit End or Duration: If the end list has no instances greater than \(B\), and no dur is defined, the interval's end is determined by the intrinsic duration of the media, the parent container boundaries, or remains unresolved (indefinite).

Step 4: Clamping with min and max Constraints

After the provisional end time is calculated, the total active duration is clamped against the element's min and max attributes:

  • If the calculated duration is less than min, the end point is extended: \[\text{End} = B + \text{min}\]
  • If the calculated duration exceeds max, the end point is shortened: \[\text{End} = B + \text{max}\]

Step 5: Applying Restart Semantics

Before finalizing the active interval, the engine checks the restart attribute against any subsequent begin instances (\(B_{\text{next}}\)) that occur between \(B\) and \(E\):

  • restart="always" (default): If a subsequent begin time \(B_{\text{next}}\) occurs while the current interval is active (\(B < B_{\text{next}} < E\)), the current interval is truncated to end at \(B_{\text{next}}\). A new interval is then immediately opened at \(B_{\text{next}}\).
  • restart="whenNotActive": Any begin instances occurring while \(B \le t < E\) are discarded or ignored. The active interval runs to its scheduled end.
  • restart="never": The element can only play once during the parent's lifecycle; all future begin instances are permanently ignored.

Step 6: Advancing and Pruning

Once an interval completes or is truncated:

  1. The finished interval is committed to the playback history.
  2. The engine prunes instances from the begin and end lists that are no longer relevant to future intervals (typically instances older than the active interval start).
  3. The process repeats from Step 2 to locate the next active interval.
