Why Chrome Reversed Its SVG SMIL Deprecation

In 2015, Google Chrome announced its intention to deprecate Synchronized Multimedia Integration Language (SMIL) for SVG animations in favor of CSS animations and the Web Animations API, only to officially suspend that deprecation in 2017. The initial push to remove SMIL was driven by maintenance overhead, security concerns, and architectural redundancy within the Blink rendering engine. However, intense pushback from web developers, combined with the realization that alternative technologies could not replicate SMIL’s unique capabilities—particularly path morphing, complex declarative timelines, and standalone image animation—forced the Chromium team to reconsider and maintain support.

The Initial Decision: Why Chrome Targeted SMIL

The Chromium project initially flagged SMIL for deprecation in Chrome 45 (2015) for several architectural and strategic reasons:

  • Engine Complexity and Maintenance: SMIL was notoriously complex to implement and maintain within Blink and WebKit. It introduced significant code overhead, frequent edge-case bugs, and potential attack surfaces for security vulnerabilities.
  • Redundancy with Web Standards: The Chromium team envisioned a unified animation architecture. At the time, both CSS Animations and the emerging Web Animations API (WAAPI) were viewed as modern, performant replacements that would standardize how animations were executed across HTML and SVG.
  • Lack of Universal Browser Support: Microsoft never implemented SMIL in Internet Explorer or EdgeHTML. Because cross-browser consistency was lacking, browser vendors questioned whether maintaining a niche declarative animation specification was justified.

The Developer Backlash: Why Alternatives Fell Short

When Chrome announced its plan to remove SMIL, the web standards and animation communities raised significant objections. Developers demonstrated that neither CSS nor the Web Animations API was a drop-in replacement for SMIL’s core feature set:

  • Path Morphing and Vector-Specific Capabilities: SMIL natively allows developers to animate the d attribute of SVG paths (<animate>) and guide objects along complex vectors (<animateMotion>). In 2015, CSS and JavaScript had no native, hardware-accelerated declarative equivalent for morphing complex vector shapes.
  • Standalone SVG Portability: SVG files embedded via HTML <img> tags or used as CSS background images cannot execute external scripts due to security sandboxing. SMIL animations function within these restricted contexts, allowing standalone icons and graphics to animate without JavaScript. Deprecating SMIL meant completely eliminating animated vector images in these common use cases.
  • Complex Synchronization: SMIL provided an advanced timing model, allowing animations to be chained, synced to user interactions, or triggered by other animation events purely through declarative XML attributes, without writing custom event-handling scripts.

The Reversal and Current Status

Faced with evidence that deprecating SMIL would break a substantial amount of existing web content and sever vital graphic capabilities, the Chromium team formally suspended the deprecation intent in 2017.

Chromium engineers acknowledged that until CSS and the Web Animations API could achieve full feature parity—specifically regarding declarative path animations and animated SVG images—removing SMIL was premature. While modern development has shifted predominantly toward CSS and JavaScript-based solutions for UI motion, SMIL remains actively supported across modern Chromium browsers, Firefox, and Safari, preserving backwards compatibility and specialized vector animation workflows.
