EPUB 3 Media Overlays and SMIL 3.0 Timing Syntax

EPUB 3 Media Overlays enable synchronized narration and text highlighting in digital publications by adopting a tailored subset of the W3C Synchronized Multimedia Integration Language (SMIL) 3.0. Rather than implementing the full, complex SMIL specification, EPUB 3 relies primarily on SMIL 3.0's Timing and Synchronization module alongside select media elements. This integration creates a deterministic, linear timeline that matches recorded audio to distinct DOM fragments within XHTML documents.

The SMIL 3.0 Structural Model in EPUB 3

Media Overlays use SMIL documents (files with a .smil extension) structured strictly around two fundamental SMIL 3.0 temporal containers: <seq> and <par>.

  • <seq> (Sequence): Represents elements played in chronological succession. In EPUB 3, the root container is typically a <seq> element that maps to the sequential reading order of the corresponding EPUB Content Document.
  • <par> (Parallel): Groups media objects that must play simultaneously. Each <par> represents a discrete synchronization point, typically containing exactly one visual reference (<text>) and one audio reference (<audio>).

When a Reading System reaches a <par> block, it executes both child elements concurrently: the audio plays while the targeted textual element is highlighted.

Timing Syntax and Clock Values

SMIL 3.0 timing in EPUB 3 is defined using temporal clipping attributes on the <audio> element: clipBegin and clipEnd. These attributes specify the exact temporal segment of an external audio file assigned to that synchronization unit.

EPUB 3 conforms directly to the SMIL 3.0 Clock Values syntax for these attributes. Clock values can be expressed in three primary formats:

  1. Full-Clock Values: Composed of hours, minutes, seconds, and optional fractions of a second formatted as hh:mm:ss[.fraction] (e.g., clipBegin="00:01:23.450").
  2. Partial-Clock Values: Composed of minutes, seconds, and optional fractions formatted as mm:ss[.fraction] (e.g., clipEnd="01:28.125").
  3. Timecount Values: Expressed as a raw number followed by an optional metric unit:
    • Seconds: 12.5s
    • Milliseconds: 12500ms
    • Default (unitless numbers are interpreted as seconds): 12.5

If clipBegin is omitted, playback starts at the beginning of the audio file (0s). If clipEnd is omitted, playback continues until the physical end of the media resource.

Granular Mapping with URI Fragment Identifiers

The timing defined by SMIL 3.0 clock values coordinates with the layout engine via URI references. The <text> element contains a src attribute targeting an XHTML element's unique id through a fragment identifier (e.g., <text src="chapter1.xhtml#sentence-1" />).

The playback engine synchronizes the audio segment bounded by clipBegin and clipEnd to the visual rendering of the target element. As the audio playback time progresses between these offsets, the reading system applies styling (such as a highlight class defined in the package metadata) to that specific DOM node.

Constraints on Full SMIL 3.0

To ensure lightweight parsing and predictable rendering across dedicated e-readers and mobile devices, EPUB 3 explicitly restricts several advanced SMIL 3.0 timing capabilities:

  • No Non-Linear Timing: Event-based triggers (such as begin="id.click"), interactive timing, and dynamic run-time adjustments are omitted.
  • No Nested Parallel Containers: Complex layouts with nested <par> elements running concurrent audio channels or overlapping text highlights are disallowed.
  • Strict Linearity: The document timeline must be deterministic, preventing cyclic timing loops, conditional execution (<switch>), and indeterminate durations (dur="indefinite").

By implementing a well-defined subset of SMIL 3.0 timing syntax, EPUB 3 delivers synchronized audio-e-book experiences with precise temporal control while avoiding the complexity of a full-scale multimedia runtime engine.
