SMIL WCAG Accessibility Compliance Tools

This article outlines the specific software, validators, and evaluation methodologies used to verify Synchronized Multimedia Integration Language (SMIL) files for accessibility compliance against the Web Content Accessibility Guidelines (WCAG). Because standalone automated tools dedicated exclusively to SMIL accessibility are limited, compliance verification relies on a combination of digital publishing checkers, XML-based automated linters, and targeted manual inspection.

Ace by DAISY and DAISY Pipeline

The primary production use of SMIL today is within EPUB 3 Media Overlays and DAISY digital talking books to synchronize audio with on-screen text. The DAISY Consortium provides the leading tools for testing these implementations:

  • Ace by DAISY: Ace is an open-source accessibility checking tool that evaluates EPUB files against WCAG 2.0/2.1/2.2 and the EPUB Accessibility Specification. It examines SMIL files within the publication to ensure media overlays are structurally mapped to text elements, flagging missing synchronization references or broken linkages.
  • DAISY Pipeline 2: This cross-platform processing framework contains built-in validation routines for DAISY and EPUB formats, ensuring SMIL timing files accurately mirror the visual reading order and hierarchy required by WCAG Principle 1 (Perceivable).

XML and Schematron Validation Tools

Because SMIL is an XML-based markup language, developers enforce WCAG requirements by combining standard XML validators with custom Schematron rule sets:

  • W3C XML Schema Validation: General XML validators (such as xmllint or Apache Xerces) verify the document against the W3C SMIL specification schemas. They ensure required attributes, such as alt, longdesc, and system test attributes (systemCaptions, systemAudioDesc, systemOverdubOrSubtitle), are syntactically correct.
  • Custom Schematron Engines: Accessibility engineers use Schematron (implemented via tools like Saxon) to create assertions mapped directly to WCAG Success Criteria. For example, a Schematron rule can verify that every video element in a SMIL playlist contains an associated synchronized text stream for captions (WCAG 1.2.2) or an alternate audio track for audio descriptions (WCAG 1.2.5).

Reference Players for Functional Verification

Automated tools cannot determine whether captions match spoken audio or whether playback controls are fully accessible. Functional testing requires dedicated accessible user agents:

  • Thorium Reader: An open-source desktop reading application built by the European Digital Reading Lab (EDRLab). It fully supports EPUB 3 Media Overlays and SMIL synchronization, allowing testers to verify that synchronized content respects keyboard navigation, text resizing, and user-selected contrast settings.
  • Accessible Media Player Emulators: Testing SMIL playback in tools like VLC or QuickTime (which maintain varying levels of legacy SMIL support) verifies whether test attributes toggle captions and audio descriptions automatically based on user-agent preferences.

Key WCAG Criteria to Audit Manually

Because no automated tool can guarantee full WCAG compliance for SMIL, manual verification must cover:

  • SC 1.2.2 (Captions - Prerecorded): Confirming that text elements referenced in SMIL <par> or <seq> groups accurately reflect dialogue, speaker identification, and crucial sound effects.
  • SC 1.2.5 (Audio Description - Prerecorded): Ensuring secondary audio elements timed alongside primary video tracks provide clear descriptions of critical visual actions without conflicting with dialogue.
  • SC 1.4.2 (Audio Control) and SC 2.2.2 (Pause, Stop, Hide): Verifying that any presentation utilizing SMIL allows the end user to pause, stop, or adjust the volume of synchronized audio independently from the system volume.
