What Happens When a SMIL seq Container Is Paused

When a parent Synchronized Multimedia Integration Language (SMIL) <seq> container is paused mid-playback, its entire local timeline halts immediately, freezing the currently active child element in place while delaying all upcoming sequence items. The active child's media progression and internal clock stop instantly, and subsequent children remain in an un-started state until the parent container resumes. Once playback is resumed, the active child finishes its remaining duration, and the sequence proceeds normally without losing temporal alignment.

Impact on the Currently Active Child

In a <seq> container, child elements are played one after another in chronological order, meaning only one child element is actively rendering at any given moment. When the parent <seq> container receives a pause command, the local time of the container stops advancing. Consequently:

  • Time Suspension: The active child’s local timeline freezes at the exact moment of the pause.
  • Media Freezing: Visual elements (such as images, text displays, or video frames) pause on the current frame or state. Audio elements stop outputting sound instantly.
  • State Preservation: The active child retains its active state rather than transitioning to an ended state. It does not unload or reset.

Impact on Subsequent (Upcoming) Children

Children that have not yet started playback are not instantiated or evaluated for execution while the parent is paused:

  • Delayed Start Times: In SMIL, each successive child in a <seq> element relies on the end time of the preceding child. Because the active child’s timeline is paused, its end event is delayed by the exact duration of the pause.
  • Preserved Queue: Upcoming children remain queued. Their scheduling is shifted forward on the global document timeline, ensuring that no elements are skipped, clipped, or prematurely triggered.

Impact on Completed Children

Elements in the sequence that finished playing prior to the pause event are unaffected in terms of playback logic:

  • Fill Behavior Remains Constant: If an earlier child used fill="freeze", its final frame remains frozen on the display. If it used fill="remove", it remains invisible. The pause action on the parent container does not alter the post-display behavior of previously terminated elements.

Resumption Behavior

When the parent <seq> container is unpaused or receives a resume trigger, the timeline restarts from the exact millisecond where it stopped:

  • The active child completes its remaining active duration.
  • Upon completion of the active child, an end event is fired.
  • The <seq> container catches the end event and triggers the begin event of the next child element, restoring normal sequential playback across the rest of the media presentation.
