How to Toggle Audio Descriptions in a SMIL Switch

This article explains how to configure and dynamically toggle audio descriptions for visually impaired users using the Synchronized Multimedia Integration Language (SMIL) <switch> element. You will learn how SMIL test attributes manage accessibility preferences, the limitations of static evaluation, and the technical methods—including SMIL DOM manipulation and SMIL 3.0 State expressions—required to achieve real-time dynamic switching during media playback.

In standard SMIL, alternative content choices are managed using the <switch> element combined with system test attributes. For audio descriptions, the core attribute is systemAudioDesc. A typical declarative structure presents two choices: an audio stream with descriptive narration enabled, and a standard audio stream as a fallback.

<switch>
  <audio src="audio_with_description.mp3" systemAudioDesc="on" />
  <audio src="audio_standard.mp3" />
</switch>

By default, the SMIL user agent evaluates the children of a <switch> element in sequential order at playback initialization. It selects the first child whose test attribute matches the user's system preferences. If the user has configured their media player or operating system accessibility settings to require audio descriptions, systemAudioDesc="on" evaluates to true, and the descriptive track is rendered.

To achieve dynamic toggling while the document is already rendering, you cannot rely solely on standard static attribute resolution, as <switch> does not automatically re-evaluate mid-stream. Dynamic behavior can be accomplished through two primary approaches:

1. SMIL DOM Dynamic Manipulation

If the playback engine supports the SMIL Document Object Model (DOM), user interface controls (such as an on-screen toggle button) can be bound to a script that alters the active track. When the user toggles the audio description:

  1. Target the <switch> element via the DOM.
  2. Read the current user preference from an application-level variable.
  3. Pause the media element temporarily or maintain synchronization references.
  4. Programmatically modify the active track by updating child elements or changing attributes, then trigger the SMIL container's resolution method.

2. SMIL 3.0 State Profile and Expressions

In environments supporting SMIL 3.0, dynamic evaluation is natively handled by the State profile rather than relying on legacy static test attributes. Using the expr attribute, media elements within the <switch> can evaluate dynamic variables in real time.

<smil xmlns="http://www.w3.org/ns/SMIL30">
  <head>
    <state>
      <data xmlns="">
        <audioDescEnabled>false</audioDescEnabled>
      </data>
    </state>
  </head>
  <body>
    <par>
      <video src="video.mp4" />
      <switch>
        <audio src="audio_described.mp3" expr="audioDescEnabled == 'true'" />
        <audio src="audio_standard.mp3" />
      </switch>
    </par>
  </body>
</smil>

When an event updates the audioDescEnabled value via a <setvalue> action or an external controller, the condition updates, and the SMIL player switches playback to the corresponding audio branch without requiring a full document reload.
