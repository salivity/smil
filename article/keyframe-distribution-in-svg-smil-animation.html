Keyframe Distribution in SVG SMIL Animation

Synchronized Multimedia Integration Language (SMIL) controls the timing and interpolation of SVG animations through specific XML attributes applied directly to animation elements like <animate>, <animateTransform>, and <animateMotion>. Instead of using traditional percentage symbols as seen in CSS keyframes, SMIL utilizes normalized floating-point values between 0 and 1 defined within the keyTimes attribute to establish keyframe percentage distributions. Paired with attributes such as values, calcMode, and keySplines, SMIL enables granular control over pacing, easing, and state transitions throughout an animation’s duration.

The Core Mechanism: keyTimes and values

To create keyframed behavior, SMIL coordinates two primary attributes:

  • values: A semicolon-separated list of values that the target attribute will adopt during the animation cycle.
  • keyTimes: A semicolon-separated list of normalized timestamps ranging from 0 to 1 that correspond sequentially to each entry in the values list.

Each value in keyTimes acts as a percentage checkpoint. A value of 0 represents 0% of the total animation duration (dur), 0.5 represents 50%, and 1 represents 100%.

For a valid distribution:

  1. The first value in keyTimes must be 0.
  2. The final value in keyTimes must be 1.
  3. Each intermediate value must be greater than or equal to the preceding value (strictly monotonically non-decreasing).
  4. The number of timestamps in keyTimes must exactly match the number of definitions in the values list.

Controlling Distribution with calcMode

The method by which an animation transitions between keyframe intervals depends on the calcMode attribute. SMIL supports four calculation modes:

  • linear (Default): Interpolates values smoothly at a constant rate between the keyframe percentages specified in keyTimes. If keyTimes is omitted, the duration is distributed equally across all segments defined in values.
  • discrete: Jumps abruptly from one value to the next without smooth interpolation. The animation holds the specified value until the next keyframe threshold in keyTimes is reached.
  • paced: Ignores keyTimes entirely. SMIL automatically calculates keyframe intervals to produce an animation that runs at a uniform velocity throughout its entire duration, based on the spatial distance or numeric variance between points.
  • spline: Uses cubic Bézier curves defined by the keySplines attribute to control easing between keyframes. When calcMode="spline" is used, keyTimes defines the percentage boundaries, while keySplines defines the acceleration and deceleration within each interval.

Easing Distributions with keySplines

When precision easing is required between percentage checkpoints, the keySplines attribute is used alongside keyTimes.

Because keySplines defines the transition between frames, the number of cubic Bézier definitions must be exactly one less than the total count of entries in keyTimes. Each spline takes four coordinate points (x1 y1 x2 y2), matching the standard cubic Bézier format used in CSS timing functions.

Example Implementation

The following example demonstrates an element shifting its horizontal position across uneven keyframe percentage distributions (0%, 20%, 80%, and 100%):

<svg width="200" height="100" xmlns="http://www.w3.org/2000/svg">
  <circle cx="20" cy="50" r="15" fill="crimson">
    <animate
      attributeName="cx"
      dur="4s"
      repeatCount="indefinite"
      calcMode="spline"
      values="20; 60; 140; 180"
      keyTimes="0; 0.2; 0.8; 1"
      keySplines="0.42 0 0.58 1; 0.42 0 0.58 1; 0.42 0 0.58 1" />
  </circle>
</svg>

In this setup:

  • Between 0% and 20% of the timeline (0 to 0.2), the circle moves from cx="20" to cx="60".
  • Between 20% and 80% (0.2 to 0.8), it traverses from 60 to 140.
  • Between 80% and 100% (0.8 to 1), it completes the movement from 140 to 180.
  • Each segment uses the easing curve defined in the corresponding segment of keySplines.
