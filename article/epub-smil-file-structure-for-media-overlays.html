EPUB SMIL File Structure for Media Overlays

In an EPUB 3 publication, Synchronized Multimedia Integration Language (SMIL) documents define the exact timing relationships between recorded audio and written text, powering the Media Overlays feature. This article breaks down the essential structure, required namespaces, core elements, and packaging requirements of a .smil file within an EPUB container, providing an actionable reference for developers and digital publishers looking to implement synchronized narration.

The Role of SMIL in EPUB 3

Media Overlays allow reading systems to play pre-recorded narration while simultaneously highlighting the corresponding text on the page. The .smil document acts as the synchronization map. Rather than embedding playback logic directly inside the XHTML documents, the EPUB format decouples playback into standalone XML-based SMIL files stored within the EPUB's content folder (typically OEBPS or EPUB).

Root Element and Required Namespaces

Every Media Overlay document is an XML file ending with the .smil extension. The root element is <smil>, which requires specific namespace declarations and an EPUB version attribute:

<?xml version="1.0" encoding="UTF-8"?>
<smil xmlns="http://www.w3.org/ns/SMIL" 
      xmlns:epub="http://www.idpf.org/2007/ops" 
      version="3.0">
    <body>
        <!-- Timing content goes here -->
    </body>
</smil>
  • xmlns: Specifies the default SMIL namespace (http://www.w3.org/ns/SMIL).
  • xmlns:epub: Declares the EPUB extension namespace (http://www.idpf.org/2007/ops), enabling EPUB-specific attributes like epub:textref.
  • version: Must be set to "3.0" for EPUB 3 publications.

Structural Hierarchy: <body>, <seq>, and <par>

Inside the root <smil> tag, the document is divided into structural blocks that organize how media is played back.

The <body> Element

The <body> element serves as the primary top-level container for all synchronization data in the document. An EPUB SMIL file contains exactly one <body> tag.

The Sequence Element (<seq>)

The <seq> element defines a chronological sequence of elements that must be played one after another.

  • It is commonly used to group synchronization units that belong to a particular structural section, such as a chapter, section, or page.
  • It often includes an epub:textref attribute targeting the section header or the container element in the associated XHTML file.

The Parallel Element (<par>)

The <par> element defines simultaneous playback. In EPUB Media Overlays, it groups exactly one piece of text with its corresponding audio segment. Each <par> represents an individual synchronization event, such as a single sentence or paragraph.

Media Elements: <text> and <audio>

Every <par> element must contain a paired <text> element and <audio> element.

The <text> Element

Points directly to the text element in the XHTML content file that should be highlighted during audio playback:

  • src: Contains the URI path to the target XHTML document, followed by a fragment identifier (#id) matching the id of the specific HTML element.

The <audio> Element

Defines the corresponding recorded audio segment:

  • src: The relative URI pointing to the audio file (commonly .mp3 or .m4a).
  • clipBegin: The timestamp marking the start of the audio segment.
  • clipEnd: The timestamp marking the end of the audio segment.

Timestamps follow the SMIL clock value format, most commonly expressed as HH:MM:SS.mmm (e.g., 00:01:23.450) or in raw seconds (e.g., 83.45s).

Complete Example of a .smil Document

<?xml version="1.0" encoding="UTF-8"?>
<smil xmlns="http://www.w3.org/ns/SMIL" 
      xmlns:epub="http://www.idpf.org/2007/ops" 
      version="3.0">
    <body id="chapter1_overlay">
        <seq id="seq1" epub:textref="chapter1.xhtml#heading1">
            <par id="par1">
                <text src="chapter1.xhtml#sentence1"/>
                <audio src="audio/chapter1.mp3" clipBegin="00:00:00.000" clipEnd="00:00:03.500"/>
            </par>
            <par id="par2">
                <text src="chapter1.xhtml#sentence2"/>
                <audio src="audio/chapter1.mp3" clipBegin="00:00:03.500" clipEnd="00:00:08.200"/>
            </par>
        </seq>
    </body>
</smil>

EPUB Package Integration (content.opf)

For the SMIL file to function within the EPUB container, it must be properly declared in the package manifest (content.opf):

  1. Manifest Declaration: The .smil file is listed with the media type application/smil+xml.
  2. Associating with Content: The XHTML file that contains the text must reference the SMIL file using the media-overlay attribute on its manifest entry.
  3. Audio File Declaration: Any audio files referenced by the SMIL document must also be registered in the manifest with their proper MIME types (e.g., audio/mpeg).
<manifest>
    <item id="chapter1_html" href="chapter1.xhtml" media-type="application/xhtml+xml" media-overlay="chapter1_overlay"/>
    <item id="chapter1_overlay" href="chapter1.smil" media-type="application/smil+xml"/>
    <item id="chapter1_audio" href="audio/chapter1.mp3" media-type="audio/mpeg"/>
</manifest>

This link ensures that when a reading system opens chapter1.xhtml, it immediately detects the linked chapter1.smil file and enables the synchronous playback UI for the user.
