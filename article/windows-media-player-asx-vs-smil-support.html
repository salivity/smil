Windows Media Player ASX vs SMIL Support

During the height of the streaming media wars, Microsoft took a divergent path from open web standards by implementing its proprietary Advanced Stream Redirector (ASX) format in Windows Media Player instead of adopting native support for the W3C’s Synchronized Multimedia Integration Language (SMIL). While both formats utilized XML syntax to orchestrate multimedia presentations, ASX functioned primarily as a streaming redirector and playlist control mechanism, whereas standard SMIL offered a full spatial and temporal presentation engine. This fundamental design difference dictated how Windows Media Player handled media sequencing, layout composition, and network failover compared to players that fully embraced standard SMIL.

Purpose and Architectural Scope

Standard SMIL was developed by the World Wide Web Consortium (W3C) as an open standard to orchestrate independent multimedia tracks—such as audio, video, text captions, and static graphics—into an integrated, interactive presentation. It served as a standalone presentation layer independent of the underlying media player.

In contrast, Microsoft designed ASX (specifically ASX version 3.0) as an XML metafile tailored to Windows Media Technologies. Its primary purpose was not to assemble complex multi-track visual presentations from scratch, but rather to serve as a pointer and controller for Advanced Systems Format (ASF), Windows Media Video (WMV), and Windows Media Audio (WMA) streams. ASX scripts solved the browser issue of launching media streams without downloading them entirely by handing off network URLs to the Windows Media Player executable.

Temporal Synchronization: Sequential vs. Parallel Timing

The most significant functional difference lies in timing and synchronization capabilities:

  • SMIL Timing: Standard SMIL supports robust synchronization containers. Authors can define parallel playback (<par>), where multiple media elements play simultaneously with fine-grained start and end offsets, as well as sequential playback (<seq>) and mutually exclusive playback (<excl>). This enables complex behaviors, such as playing background music while synchronizing subtitles and changing slide images at exact timestamps.
  • ASX Timing: ASX is fundamentally sequential. Presentations are organized around an <ASX> root containing multiple <ENTRY> blocks, which Windows Media Player executes sequentially like a playlist. While ASX allows clipping via <STARTTIME> and <DURATION> tags, it does not natively support parallel tracks of diverse media inside the script itself. Simultaneous audio and video synchronization had to be pre-muxed into the underlying ASF/WMV container rather than synchronized dynamically at runtime through markup.

Spatial Layout and Visual Presentation

Standard SMIL features a dedicated layout model using elements like <layout>, <root-layout>, and <region>, which allow authors to define exact coordinate grids, z-indexes, and viewports for different visual components directly inside the document.

ASX provides no native spatial layout capabilities. Windows Media Player rendered video strictly within its fixed playback canvas. While ASX supported basic supplementary content—such as displaying static graphic banners with <BANNER> and linking to external web pages using <MOREINFO>—it could not arrange multiple overlapping or adjacent visual media streams on a canvas. To achieve interactive spatial layouts, Microsoft required developers to integrate Windows Media Player into Internet Explorer using ActiveX or build proprietary Windows Media Player skins.

Network Resiliency and Streaming Directives

Where ASX matched or exceeded basic SMIL usage in Windows environments was in streaming management and server integration:

  • Failover and Redundancy: ASX provided native mechanisms for fallback streams. Using multiple <REF> elements within an <ENTRY>, content creators could specify fallback servers, alternate protocols (such as MMS, RTSP, or HTTP), and dynamic rollover paths if a primary stream failed.
  • Client-Side Parameter Injection: ASX scripts seamlessly passed parameters to Windows Media Services, handling client-side event tracking, advertising insertion, and dynamic bitrate switching optimized specifically for the Windows Media ecosystem.

Industry Trajectory and HTML+TIME

Rather than implementing standard SMIL natively into Windows Media Player, Microsoft submitted a proposal to the W3C called HTML+TIME (Timed Interactive Multimedia Extensions). This effort sought to integrate SMIL's temporal concepts directly into HTML DOM elements within Internet Explorer rather than maintaining a separate SMIL engine inside the media player. Consequently, Windows Media Player remained tethered to ASX for media delivery, while competitors like RealPlayer and QuickTime served as the primary reference implementations for standard SMIL authoring throughout the early 2000s.
