SMIL Multi-Projector Blending for Planetarium Domes

Synchronized Multimedia Integration Language (SMIL) coordinates multi-projector blending for planetarium domes by synchronizing distinct media streams, defining spatial layout configurations, and orchestrating edge-blending transitions across multiple display channels. By acting as a centralized declarative framework, SMIL ensures that separate projection feeds align perfectly in both time and space to produce a continuous, high-resolution fulldome visual experience.

Master Clock and Temporal Synchronization

Planetarium domes typically rely on an array of five to twelve high-resolution projectors to cover the entire hemispherical surface. SMIL coordinates these channels using its temporal specifications:

  • Parallel Execution (<par>): SMIL structures multi-channel playback inside parallel containers. This guarantees that video feeds mapped to different sections of the dome launch at the exact same microsecond, eliminating visual tearing between projection seams.
  • Syncbase and Event Timing: Child elements reference a master timeline or inter-element events (e.g., projector2.begin = projector1.begin). If one stream stutters, SMIL's synchronization attributes (such as syncBehavior="locked") instruct the player to hold or drop frames, maintaining strict alignment across all channels.

Spatial Layout and Channel Mapping

Before projected light can be blended, media files must be segmented and mapped to match the physical orientation of each projector inside the dome. SMIL manages this through its layout module:

  • Region Definition (<region>): The <layout> section specifies unique spatial viewports corresponding to each projector's targeted display zone. Coordinates, z-indexes, dimensions, and aspect ratios are defined per display output.
  • Master Canvas Slicing: A single hemispherical "dome master" format (such as an equirectangular or fish-eye master file) is segmented across these regions. SMIL routes the corresponding cropped and pre-warped video slice to its designated hardware output.

Overlap Management and Edge Blending Integration

Seamless panoramic projection requires adjacent projector beams to overlap by 15% to 20%. Within these overlap corridors, the system must smoothly blend brightness and color to eliminate visible bright bands:

  • Alpha Masking via Transitions: SMIL’s transition effects (<transitionFilter>) apply predefined soft-edge alpha gradient masks directly over overlapping boundaries. As pixels approach the boundary edge of an overlap zone, their intensity tapers down to match the inverse taper of the adjacent projector.
  • Hardware and Shader Handshakes: In advanced fulldome clusters, SMIL acts as the high-level coordinator that triggers specialized hardware-level warping and geometric blend algorithms. SMIL passes timing markers and asset coordinates to underlying graphics layers (such as OpenGL or specialized image-generator nodes), ensuring dynamic blending filters activate concurrently across all render units.

Distributed Cluster Architecture

Most planetariums use a distributed computing model where independent media servers feed individual projectors. SMIL facilitates coordination across this network:

  • Centralized Instruction Delivery: A central control server distributes a unified SMIL script to individual client machines driving the projectors.
  • Network Time Protocol (NTP) and PTP Alignment: When paired with precision network protocols, SMIL nodes read the shared schedule, pre-buffer media assets, and initiate playback strictly according to the coordinated timeline, preserving a unified panoramic image across the dome.
