Looping Media Tracks in SMIL Par Containers

In Synchronized Multimedia Integration Language (SMIL), looping individual media tracks inside a parallel container (<par>) is achieved using timing attributes applied directly to the target child elements. By leveraging the repeatCount and repeatDur attributes, authors can define how many times or for how long a specific audio, video, or animation track should replay independently of the other tracks executing simultaneously within the same <par> block.

The repeatCount Attribute

The primary mechanism for setting a discrete loop counter on an individual media track is the repeatCount attribute. This attribute is placed directly on the media element (such as <video>, <audio>, or <img />) rather than on the parent <par> container.

The repeatCount attribute accepts the following values:

  • Numeric Value (Integer or Decimal): Specifies the exact number of iterations. For example, repeatCount="3" plays the media asset three full times. Fractional values, such as repeatCount="2.5", play the asset twice in full and then play the first half of the track before stopping.
  • indefinite: Causes the media track to loop continuously until the parent container ends or an external event terminates playback.

Syntax Example

The following snippet demonstrates how individual media elements within a <par> tag maintain their own separate repetition counts:

<smil xmlns="http://www.w3.org/ns/SMIL" version="3.0" baseProfile="Language">
  <body>
    <par endsync="last">
      <!-- Loops exactly 3 times -->
      <video src="clip.mp4" repeatCount="3" />

      <!-- Loops continuously -->
      <audio src="ambient.mp3" repeatCount="indefinite" />

      <!-- Does not loop; plays once -->
      <img src="overlay.png" dur="15s" />
    </par>
  </body>
</smil>

Alternative: Duration-Based Looping with repeatDur

When repetition should be constrained by time rather than a fixed iteration count, SMIL provides the repeatDur attribute. It specifies the total duration during which the element repeats. For example, setting repeatDur="00:45" on an audio track with a native duration of 15 seconds will cause it to repeat exactly three times to fill the 45-second window.

Parent <par> Synchronization Controls

When setting loop counters on individual tracks, the lifespan of those loops depends on the parent <par> element's completion rules:

  1. endsync="last" (Default): The <par> block stays active until all child elements—including those with finite repetition counts—have completed. Any track marked repeatCount="indefinite" will keep the container open indefinitely unless another track explicitly dictates termination.
  2. endsync="first": The container ends as soon as the shortest non-repeating child finishes, which can prematurely stop a track mid-loop.
  3. Explicit dur on <par>: If a hard duration is assigned to the <par> container (e.g., dur="30s"), all repeating children will be cut off once that duration is reached, regardless of their individual repeatCount settings.
