Loop SMIL SVG Path Animation with Easing

This article explains how to create an infinitely looping SVG path animation using Synchronized Multimedia Integration Language (SMIL) with smooth easing. You will learn the exact syntax, the required attributes for continuous playback, and how to apply cubic-bezier spline interpolation to prevent jarring transitions during the loop.

Core Syntax Overview

To animate an SVG path with SMIL, you embed an <animate> element inside the target <path>. Achieving an infinite loop with smooth easing requires specific attributes to control repetition, return the shape to its starting state, and apply cubic-bezier timing curves.

Here is the complete implementation syntax:

<svg viewBox="0 0 100 100" xmlns="http://www.w3.org/2000/svg">
  <path d="M10,50 Q50,20 90,50" fill="none" stroke="black" stroke-width="2">
    <animate
      attributeName="d"
      dur="4s"
      repeatCount="indefinite"
      calcMode="spline"
      values="
        M10,50 Q50,20 90,50;
        M10,50 Q50,80 90,50;
        M10,50 Q50,20 90,50"
      keyTimes="0; 0.5; 1"
      keySplines="
        0.42 0.0 0.58 1.0;
        0.42 0.0 0.58 1.0"
    />
  </path>
</svg>

Attribute Breakdown

1. Infinite Looping

  • repeatCount="indefinite": Tells the browser to restart the animation automatically each time it finishes.
  • values: Contains semicolon-separated path definitions. To ensure a seamless loop without a sudden jump at the restart point, the final path definition must match the initial path definition (Path A -> Path B -> Path A). Each path string must contain the exact same number and type of path commands.

2. Smooth Easing (Splines)

  • calcMode="spline": Enables custom cubic-bezier interpolation instead of the default linear or paced timing.
  • keyTimes: A semicolon-separated list of time values from 0 to 1 that correspond to the items defined in values. With three states, use "0; 0.5; 1".
  • keySplines: Defines the Bézier control points (x1 y1 x2 y2) for the transition between each interval. There must be one fewer set of control points than there are keyTimes. The value 0.42 0.0 0.58 1.0 replicates the smooth acceleration and deceleration of CSS ease-in-out.
