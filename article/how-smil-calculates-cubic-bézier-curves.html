How SMIL Calculates Cubic Bézier Curves

This article provides an overview of how Synchronized Multimedia Integration Language (SMIL) uses cubic Bézier curves to calculate smooth acceleration and deceleration during animations. It covers the underlying mathematical principles of cubic Bézier interpolation, explains how SMIL translates normalized time into visual property changes through attributes like keySplines, and details the numerical algorithms engines use to solve parametric equations for real-time frame rendering.

Defining Splines in SMIL

In SVG and SMIL, pacing is controlled via the calcMode="spline" attribute combined with keySplines. When using splines, each interval between two keyframes is governed by a cubic Bézier curve defined by two control points: \((x_1, y_1)\) and \((x_2, y_2)\).

The curve operates inside a normalized coordinate space ranging from \((0,0)\) to \((1,1)\):

  • \(P_0 = (0, 0)\): The start of the time interval and property value.
  • \(P_1 = (x_1, y_1)\): The first control point, determining the initial tangent and acceleration.
  • \(P_2 = (x_2, y_2)\): The second control point, determining the final tangent and deceleration.
  • \(P_3 = (1, 1)\): The end of the time interval and property value.

The \(x\)-coordinates correspond to normalized time elapsed within the interval, and must stay within the range \([0, 1]\). The \(y\)-coordinates correspond to the progression of the animated attribute and can occasionally exceed \([0, 1]\) for overshoot or bounce effects.

The Mathematical Formula

A cubic Bézier curve is a parametric curve defined by a parameter \(t\), where \(t \in [0, 1]\). The general formula is:

\[B(t) = (1 - t)^3 P_0 + 3(1 - t)^2 t P_1 + 3(1 - t) t^2 P_2 + t^3 P_3\]

Because \(P_0 = (0,0)\) and \(P_3 = (1,1)\), the explicit parametric functions for the time component \(X(t)\) and the value component \(Y(t)\) simplify to:

\[X(t) = 3(1 - t)^2 t x_1 + 3(1 - t) t^2 x_2 + t^3\] \[Y(t) = 3(1 - t)^2 t y_1 + 3(1 - t) t^2 y_2 + t^3\]

Expanding both functions in terms of standard polynomial coefficients yields:

\[X(t) = (1 - 3x_2 + 3x_1)t^3 + (3x_2 - 6x_1)t^2 + 3x_1 t\] \[Y(t) = (1 - 3y_2 + 3y_1)t^3 + (3y_2 - 6y_1)t^2 + 3y_1 t\]

Finding Value from Time: Solving for Parameter \(t\)

In an animation runtime, the known input is normalized elapsed time, \(T_X\) (where \(T_X = X(t)\)), and the engine must determine the corresponding output value factor \(Y(t)\). Because the parametric equation defines \(X\) as a function of \(t\) rather than \(Y\) directly as a function of \(X\), the SMIL engine must solve for \(t\) such that:

\[f(t) = X(t) - T_X = 0\]

Because an analytical solution to this cubic equation is computationally expensive to evaluate across millions of frames, rendering engines use numerical root-finding algorithms:

  1. Newton-Raphson Iteration: The engine begins with an initial guess (often \(t_0 = T_X\)). It iteratively refines the guess using the derivative of \(X(t)\) with respect to \(t\): \[t_{n+1} = t_n - \frac{X(t_n) - T_X}{X'(t_n)}\] The derivative \(X'(t)\) is computed directly from the polynomial coefficients: \[X'(t) = 3(1 - 3x_2 + 3x_1)t^2 + 2(3x_2 - 6x_1)t + 3x_1\] Usually, 4 to 8 iterations of Newton-Raphson provide sufficient precision for sub-pixel display accuracy.

  2. Bisection Method (Fallback): If the slope \(X'(t)\) approaches zero or the iteration fails to converge rapidly, the engine switches to a binary search (bisection) over the interval \([0, 1]\) to guarantee finding the correct root \(t\).

Mapping to Property Output

Once the parameter \(t\) is calculated for the given time \(T_X\), the engine evaluates \(Y(t)\):

\[\text{Factor} = Y(t)\]

This factor is then applied to interpolate between the starting value (\(V_{\text{start}}\)) and ending value (\(V_{\text{end}}\)) of the animated attribute:

\[\text{Current Value} = V_{\text{start}} + \text{Factor} \times (V_{\text{end}} - V_{\text{start}})\]

Rate of Change: Acceleration and Deceleration

The perceived acceleration and deceleration correspond directly to the slope of the curve, given by the derivative of \(Y\) with respect to \(X\):

\[\frac{dY}{dX} = \frac{Y'(t)}{X'(t)}\]

  • Acceleration (Ease-in): Setting a small \(y_1\) relative to \(x_1\) results in a low initial derivative (\(dY/dX \approx 0\)). The output value changes minimally as time elapses at the beginning. As \(t\) increases, the slope steepens, accelerating the animation.
  • Deceleration (Ease-out): Setting \(y_2\) near \(1\) while \(x_2\) remains low causes the curve to flatten toward the end. The derivative drops toward zero near \((1,1)\), slowing down the rate of change for a smooth stop.
  • Ease-in-out: Setting both a low initial slope (\(y_1 \approx 0\)) and a flat final slope (\(y_2 \approx 1\)) produces an S-curve that smoothly accelerates from rest, reaches peak velocity in the middle, and gently decelerates to the destination.
