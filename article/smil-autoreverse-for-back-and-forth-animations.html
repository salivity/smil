SMIL autoReverse for Back-and-Forth Animations

The autoReverse attribute in Synchronized Multimedia Integration Language (SMIL) provides a native declarative method for creating back-and-forth or bouncing motions without requiring duplicated keyframes. By setting this timing attribute to run automatically in reverse after completing its forward cycle, developers can generate seamless bidirectional animations—often referred to as a "ping-pong" or "yo-yo" effect. This article explains how autoReverse works, its impact on timeline duration, and how it simplifies declarative animation markup.

The Core Mechanism of autoReverse

In standard SMIL animations, an element interpolates from its initial state (defined by attributes such as from or the first entry in values) to its end state (defined by to or the final entry). Once the duration (dur) finishes, the animation resets abruptly to the beginning if it loops, creating a discontinuous jump.

When autoReverse="true" is declared, the animation engine modifies the playback trajectory. The element transitions from its starting value to its end value, and upon reaching the target, it immediately plays backward from the end value back to the starting value. This interpolation occurs symmetrically, reversing properties such as translation, opacity, color, or scale smoothly.

Timeline and Duration Behavior

Understanding the temporal impact of autoReverse is critical for synchronizing multiple elements.

  • Cycle Duration: When autoReverse is enabled, the simple duration specified by the dur attribute applies to the forward motion. The reverse motion also takes the same amount of time. Consequently, one complete forward-and-backward cycle takes twice the specified simple duration (\(2 \times \text{dur}\)).
  • Active Duration: If an active duration (repeatDur) or repeat count (repeatCount) is defined, the engine counts the complete round trip (forward and backward) as the baseline cycle.

Creating Continuous Bouncing Loops

To produce an ongoing bouncing or oscillating effect, autoReverse="true" is paired with repeatCount="indefinite".

<animate 
    attributeName="cy" 
    from="50" 
    to="200" 
    dur="1s" 
    autoReverse="true" 
    repeatCount="indefinite" />

In this scenario:

  1. The animated object moves vertically from cy="50" to cy="200" over 1 second.
  2. The autoReverse attribute activates, moving the object from cy="200" back to cy="50" over another 1 second.
  3. Because repeatCount="indefinite" is set, this 2-second cycle repeats continuously without visible seam or abrupt resets.

Advantages Over Manual Keyframing

Without autoReverse, achieving a back-and-forth animation requires explicitly defining intermediate points using the values and keyTimes attributes:

<!-- Manual approach without autoReverse -->
<animate 
    attributeName="cy" 
    values="50; 200; 50" 
    keyTimes="0; 0.5; 1" 
    dur="2s" 
    repeatCount="indefinite" />

While the manual approach achieves a similar visual outcome, using autoReverse offers distinct advantages:

  • Cleaner Markup: Eliminates redundant value definitions and manual pacing calculations.
  • Maintainability: Adjusting the target value requires editing only a single attribute (to) rather than multiple points across an array of values.
  • Easing Consistency: Spline-based easing applied to the animation curve automatically mirrors during the reverse segment, maintaining consistent acceleration and deceleration dynamics.
