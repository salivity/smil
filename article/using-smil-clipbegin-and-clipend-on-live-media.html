Using SMIL clipBegin and clipEnd on Live Media

This article provides an overview of how the clipBegin and clipEnd attributes operate within Synchronized Multimedia Integration Language (SMIL) when applied to live streaming media. It explains the mechanics of trimming continuous feeds, the use of wallclock timing for live broadcasts, how streaming servers interpret these attributes for time-shifted playback, and the key differences between clipping live content versus on-demand files.

The Purpose of clipBegin and clipEnd

In SMIL, clipBegin and clipEnd (often synonymous with clip-begin and clip-end in SMIL 1.0) define sub-clips of continuous media objects such as audio and video. While their primary use in Video-on-Demand (VOD) is specifying an offset from the start of a pre-recorded file, their function shifts when applied to live media streams that do not possess a fixed, static timeline.

Function on Live Streaming Media

When applied to live broadcasts, clipBegin and clipEnd serve several specific functions:

1. Defining Wallclock Time Windows

Live streams do not have an inherent starting point of zero seconds in the same way a stored file does. To address this, SMIL allows clipBegin and clipEnd to accept wallclock() values based on real-world time (UTC or local time with offsets).

  • clipBegin="wallclock(2024-05-01T15:00:00Z)": Instructs the player or media server to begin capturing or rendering the live stream at that exact real-world timestamp.
  • clipEnd="wallclock(2024-05-01T16:00:00Z)": Stops presentation or recording when that real-world time is reached.

This functionality is commonly used in scheduled programming, allowing a continuously running live feed to be partitioned into distinct program blocks.

2. DVR and Time-Shifted Playback

If the live stream is hosted on a media server that maintains a rolling recording buffer (such as HLS or DASH live-edge buffers), clipBegin can be used to start playback at a historical point in the live stream rather than at the current live edge.

  • Using an offset value (such as Normal Play Time, e.g., clipBegin="30s"), the client or server determines playback relative to the beginning of the broadcast session or buffer availability.
  • clipEnd specifies an exit point, allowing viewers to watch a specific segment within the live stream without continuing into the ongoing real-time feed.

3. Live-to-VOD and Virtual Clipping

Media servers (such as Wowza Streaming Engine or legacy streaming platforms) use SMIL playlists containing clipBegin and clipEnd to generate virtual channels or extract VOD assets directly from an active broadcast. Specifying these parameters tells the streaming engine to slice a specific range of packets out of the incoming live feed for archiving, rebroadcasting, or ad-insertion boundaries.

Behavior and Fallbacks

  • Unsupported Seeking: If a client or streaming protocol does not support seeking or time-shifting within a live broadcast, the player will typically ignore relative clipBegin offsets and default to playing from the current live point.
  • Exceeding the Buffer: If clipBegin references a point in time that has already expired from a server's live DVR cache, the server will either return an error or start playback at the earliest available segment.
  • Automatic Termination: Once the stream's timeline reaches the point designated by clipEnd, the media element becomes inactive, freeing the SMIL presentation to transition to the next scheduled element or terminate cleanly.
