SMIL Split-Screen Video and Asynchronous Refresh

Synchronized Multimedia Integration Language (SMIL) enables multi-zone layouts by orchestrating concurrent media streams through discrete spatial regions and temporal synchronization containers. When handling split-screen video playback involving media or displays with asynchronous refresh rates, SMIL separates high-level timeline scheduling from the underlying graphics rendering layer. This architecture allows individual media decoders and presentation engines to render independently according to their native frame rates while remaining aligned with a shared, overarching presentation timeline.

Spatial Regions and Parallel Execution

SMIL achieves split-screen architecture by decoupling visual placement from time-based scheduling. Within the <head> section, the <layout> element defines separate <region> tags, each assigned distinct spatial coordinates, dimensions, and z-indices.

In the <body> element, video assets targeting these regions are grouped within a parallel container (<par>). The <par> container instructs the SMIL player to initiate and play multiple media elements concurrently:

<smil>
  <head>
    <layout>
      <root-layout width="1920" height="1080" />
      <region id="left_screen" left="0" top="0" width="50%" height="100%" />
      <region id="right_screen" left="50%" top="0" width="50%" height="100%" />
    </layout>
  </head>
  <body>
    <par>
      <video src="stream1.mp4" region="left_screen" />
      <video src="stream2.mp4" region="right_screen" />
    </par>
  </body>
</smil>

By isolating media elements into discrete regions, SMIL avoids coupling the display hardware properties of one stream to another.

Decoupling Media Clocks from Hardware Refresh Rates

SMIL relies on an abstract presentation clock rather than hardware-driven vertical synchronization (V-Sync) intervals. Refresh rates—such as a 60 Hz panel playing alongside a 59.94 Hz or 120 Hz feed—operate at the graphics rasterizer and compositor level, whereas SMIL operates strictly at the document object and timeline layer.

When two videos in a split-screen configuration have different native frame rates (for example, 24 fps and 60 fps) or are rendered across displays with independent refresh cycles, the SMIL runtime relies on the underlying media engine (such as GStreamer, DirectShow, or HTML5/browser engines) to handle hardware composition. The SMIL interpreter handles start times, durations, and spatial positioning, while the rendering engine delegates each visual stream to separate hardware overlay planes, GPU textures, or compositor surfaces.

Because each region maps to its own decoding thread or hardware pipeline, one stream's refresh or frame delivery does not block the other.

Managing Sync Drift and Slip Behavior

In asynchronous environments, clock drift inevitably occurs due to differences in media encoding, hardware clock variations, or display timing. SMIL handles these discrepancies through fine-grained synchronization attributes:

  • syncBehavior: Dictates how strictly an element must adhere to the timeline. Setting syncBehavior="locked" forces the player to drop or duplicate frames to maintain parity with the master clock. Setting syncBehavior="canSlip" permits a stream to drift independently if an asynchronous refresh rate or decoding bottleneck stalls frame delivery, ensuring the other split-screen video continues uninterrupted.
  • syncTolerance: Defines the acceptable temporal deviation window before the SMIL runtime enforces a hard correction (such as a frame seek or pause).
  • syncMaster: Designates one media element as the authoritative clock for the entire <par> container. If one video corresponds to an unpredictable stream or an asynchronous refresh display, setting the alternate, stable stream as the syncMaster prevents playback stutter across the combined layout.

By relying on timeline synchronization rather than hardware-level frame locking, SMIL allows split-screen media with mismatched, asynchronous frame and refresh rates to coexist cleanly without introducing global pipeline stalls or cross-stream frame tearing.
