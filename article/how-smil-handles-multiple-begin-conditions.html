How SMIL Handles Multiple Begin Conditions

In Synchronized Multimedia Integration Language (SMIL), separating multiple begin conditions with semicolons allows an element to trigger across a series of distinct timing events, clock values, or user interactions. This article explains how the SMIL timing model processes semicolon-delimited values within the begin attribute, how it compiles an instance times list, and how runtime restart rules dictate when an element actually plays.

The Logical OR Behavior

When an element defines multiple begin values separated by semicolons (for example, begin="2s; click; target.end"), SMIL treats these values as an "OR" condition. The element does not wait for all conditions to occur simultaneously. Instead, satisfying any individual condition in the list can trigger the element to begin.

The Instance Time List

Under the SMIL timing architecture, multiple begin conditions generate an internal schedule known as the Instance Time List:

  1. Resolution: Each condition in the semicolon-separated list is evaluated independently. A condition can be an absolute clock value (e.g., 5s), a syncbase value referencing another element (e.g., animA.begin + 1s), or an event-based trigger (e.g., click).
  2. Chronological Sorting: The engine resolves these conditions into specific timestamps and sorts them into the instance list chronologically, rather than the order in which they appear in the attribute string.
  3. Dynamic Additions: For interactive conditions (such as a mouse click), instance times are added to the list dynamically whenever the user triggers the event.

The element will start playing at the earliest valid instance time presented by the list.

The Impact of the Restart Attribute

While multiple conditions allow multiple begin opportunities, how the element responds to subsequent triggers after the initial playback is determined entirely by the restart attribute:

  • restart="always" (Default): The element restarts immediately whenever any condition in the semicolon-separated list resolves, even if the element is currently in the middle of playing.
  • restart="whenNotActive": If a condition triggers while the element is currently active, that trigger is ignored. Conditions only initiate playback if the element has reached its end or has not yet started.
  • restart="never": The element plays only once. The first condition in the list to evaluate initiates playback, and all other conditions in the semicolon-separated list are permanently ignored for the remainder of the document's timeline.

Order Independence

The position of conditions within the semicolon-separated list does not enforce execution priority. For instance, begin="10s; 2s" will cause the element to begin at 2 seconds first, because the SMIL engine evaluates timeline values by their temporal occurrence rather than their positional syntax in the markup.
