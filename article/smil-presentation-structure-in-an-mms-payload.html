SMIL Presentation Structure in an MMS Payload

Synchronized Multimedia Integration Language (SMIL) acts as the presentation engine inside a Multimedia Messaging Service (MMS) payload, organizing how text, images, and audio display on a user's device. Delivered within a standard MIME multipart container, the SMIL document defines the screen layout, visual regions, and the timeline or sequence of the media elements. Understanding how SMIL is structured within an MMS message reveals how modern carriers and mobile operating systems render slide-based multimedia messages.

The MIME Multipart/Related Wrapper

An MMS message payload is transmitted as a binary-encoded or raw MIME entity, specifically using the multipart/related media type.

In this structure:

  • The outermost Content-Type header specifies multipart/related and points to the presentation control document via a start parameter (e.g., Content-Type: multipart/related; start="<manifest.smil>"; type="application/smil").
  • The SMIL file itself is placed as one of the constituent MIME parts, usually designated as application/smil.
  • All accompanying assets (JPEG, PNG, AMR audio, plain text files) are separate MIME body parts separated by boundary strings, each labeled with a unique Content-ID or Content-Location header.

The SMIL Document Architecture

The SMIL file functions like a lightweight HTML and CSS package optimized for mobile rendering. It is structured into two main sections within a root <smil> tag: the <head> and the <body>.

<smil>
  <head>
    <layout>
      <root-layout width="320px" height="480px"/>
      <region id="Image" top="0" left="0" width="320px" height="320px" fit="meet"/>
      <region id="Text" top="320px" left="0" width="320px" height="160px"/>
    </layout>
  </head>
  <body>
    <par dur="5000ms">
      <img src="cid:image1.jpg" region="Image" />
      <text src="cid:text1.txt" region="Text" />
    </par>
    <par dur="5000ms">
      <img src="cid:image2.jpg" region="Image" />
      <audio src="cid:audio1.amr" />
    </par>
  </body>
</smil>

1. The <head> Section: Spatial Layout

The <head> contains the <layout> element, which dictates the spatial geometry of the presentation:

  • <root-layout>: Sets the overall dimensions (width and height) of the MMS viewport.
  • <region>: Divides the screen into specific rectangular zones using attributes such as id, top, left, width, height, and fit. Common regions include dedicated spaces for media (region id="Image") and captions (region id="Text").

2. The <body> Section: Temporal Sequencing

The <body> element controls the timeline and links media assets to their respective screen regions:

  • <par> (Parallel): Represents a single "slide" or frame. All media tags placed inside a <par> tag execute simultaneously for a designated duration (e.g., dur="5000ms").
  • Media References: Tags like <img>, <text>, <audio>, and <video> point to the accompanying MIME parts. The src attribute matches the Content-ID (often prefixed with cid:) or the Content-Location header of the corresponding MIME part in the MMS wrapper. The region attribute specifies which <region> from the <head> renders the content.

Payload Resolution and Rendering

When a mobile handset receives the MMS payload, it executes the following steps:

  1. Identifies the Controller: The MMS client inspects the multipart/related header, finds the start parameter, and isolates the SMIL part.
  2. Builds the Canvas: It evaluates the <head> layout and constructs the visual bounds on the display.
  3. Resolves Identifiers: It maps the src references in the SMIL body to the binary media parts attached within the MIME boundaries.
  4. Executes the Timeline: The client presents each <par> block sequentially, rendering images and text in their assigned layout blocks while playing audio channels simultaneously for the specified duration.
