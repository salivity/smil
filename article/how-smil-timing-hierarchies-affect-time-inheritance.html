How SMIL Timing Hierarchies Affect Time Inheritance

This article examines how Synchronized Multimedia Integration Language (SMIL) timing hierarchies govern the propagation and inheritance of time transformations to descendant elements. In SMIL, time containers establish localized temporal coordinate systems, meaning that any manipulation of a parent container's clock—including rate adjustments, non-linear pacing, direction reversals, and boundary clipping—fundamentally reshapes the temporal context of its children. Understanding this cascading relationship is essential for accurately orchestrating complex, nested multimedia presentations.

Temporal Coordinate Systems and Time Containers

SMIL defines timing through hierarchical time containers: <par> (parallel), <seq> (sequence), and <excl> (exclusive). Each time container establishes its own local time space. Rather than synchronizing directly with the global presentation timeline, child elements synchronize with the local time of their immediate parent container.

When a parent container defines a timeline, it exposes a local clock to its children. A child’s active time is calculated relative to this local clock. Consequently, any modification to the parent's temporal progression shifts the baseline from which all descendant start times, durations, and end times are evaluated.

Multiplicative Rate Transformations

The speed attribute controls the rate at which time progresses within an element. When applied across a hierarchy, speed transformations are cumulative and multiplicative:

  • If a parent container has a speed="2.0" and a nested child element has a speed="1.5", the child progresses at three times (2.0 × 1.5 = 3.0) the normal presentation rate.
  • Negative speed values invert the direction of time. If a parent container runs in reverse (speed="-1.0"), the child element also plays backward relative to the global document time, even if the child's local speed attribute is positive.

The child does not override the parent's playback rate; it scales its own local clock within the already transformed clock of the parent.

Non-Linear Transformations: Acceleration and Deceleration

SMIL allows pacing alterations via attributes such as accelerate, decelerate, and autoReverse. These create non-linear mappings between an element's simple duration and its parent time:

  • Accelerate and Decelerate: When applied to a parent, these attributes warp the parent’s internal clock, producing an ease-in or ease-out effect. Descendants inherit this warped temporal progression. Even if a child element has a linear playback profile, its actual rendering accelerates and decelerates according to the parent container's curve.
  • AutoReverse: If a parent specifies autoReverse="true", the entire container plays forward for its duration and then reverses. The child elements execute normally during the forward phase and in exact reverse during the backward phase, preserving their state transitions symmetrically.

Boundary Clipping and Active Durations

A child element's timeline is strictly bounded by the active duration of its parent container. Regardless of a child’s intrinsic or specified duration:

  1. Parent Termination: When a parent container ends—whether determined by an explicit dur, an end event, or an endsync condition—all active descendants are immediately clipped and terminated. A child element cannot run past the active boundary of its parent time container.
  2. Repetition: If a parent container repeats (repeatCount or repeatDur), the entire child hierarchy resets and replays according to the parent's repetition cycle, effectively restarting the local time space for all nested elements.

Syncbase Relationships Across Nested Boundaries

When child elements use syncbase timing (e.g., begin="sibling.begin+2s"), the sync relationship resolves within the shared local time container. If the syncbase targets an element outside its immediate container, the timing engine must map time up to the nearest common ancestor and back down to the target. In this scenario, time transformations applied to the parent container warp the observed offset, scaling or delaying the synchronization point relative to external elements.
