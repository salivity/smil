Recreating SMIL Timing with Web Components and RxJS

Synchronized Multimedia Integration Language (SMIL) historically enabled sophisticated declarative animation timing, syncbases, and event-handling directly within SVG markup, but its deprecation and inconsistent browser support left a gap in modern web animation architectures. By combining custom Web Components for declarative markup with RxJS (Reactive Extensions for JavaScript) for stateful event streaming, modern web developers can replicate SMIL’s complex timing graphs—such as chained triggers, delays, and coordinate syncbases—inside a modern, modular, and reactive framework.

Understanding SMIL Timing Semantics

SMIL relied on declarative timing attributes such as begin, dur, end, repeatCount, and event-driven triggers (for example, begin="button.click + 2s" or begin="anim1.end"). These rules allowed animations to respond to user interactions, run concurrently, or form interdependent execution chains. Replicating this behavior requires two elements: a declarative interface accessible in HTML or SVG, and a temporal state machine capable of scheduling, delaying, and composing asynchronous events.

The Role of Web Components

Custom Elements provide the declarative layer once offered by native SMIL tags like <animate> and <set>. Developers define custom elements—such as <rx-timeline>, <rx-animate>, or <rx-parallel>—which parse timing attributes from the DOM.

The custom element life cycle (connectedCallback, attributeChangedCallback, and disconnectedCallback) initializes the timing model, reads attributes (such as trigger, delay, and duration), and establishes teardown mechanisms. By avoiding shadow DOM boundaries when targeting external SVG nodes, or using standard id references across the document, the custom element acts as a bridge between the DOM tree and the underlying animation pipeline.

Managing Time and Synchronization with RxJS

RxJS operates as the timing engine, translating discrete user actions, delays, and animation lifecycles into composable Observables.

  1. Event-Driven Triggers: SMIL's begin="element.click" translates into fromEvent(element, 'click'). Additional offsets like + 2s are applied using the delay operator:

    const start$ = fromEvent(triggerElement, 'click').pipe(delay(2000));

  2. Syncbase Timing (Chained Animations): In SMIL, animations can begin relative to the start or end of another animation (anim1.end). In RxJS, an animation's execution is represented as an Observable stream that emits upon completion. Downstream animations subscribe to this completion stream, mimicking syncbase relationships:

    const anim1Complete$ = new Subject();
const anim2Start$ = anim1Complete$.pipe(delay(500));

  3. Repetition and Loops: SMIL's repeatCount attribute is handled using the repeat or take operators, allowing loops to run indefinitely or terminate after a set number of iterations.

  4. Coordination and Resolution: When multiple conditions control an animation’s lifecycle (such as starting on a click but terminating if another element is hovered), operators such as takeUntil, race, or combineLatest handle conflict resolution deterministically without race conditions.

Bridging RxJS to the Web Animations API

While RxJS controls the scheduling, the actual visual changes are best handled through the Web Animations API (WAAPI) or direct CSS variable manipulation.

Inside the Web Component, the resolved RxJS stream triggers the animation:

class RxAnimateComponent extends HTMLElement {
  connectedCallback() {
    const target = document.querySelector(this.getAttribute('target'));
    const delayMs = parseFloat(this.getAttribute('delay') || '0') * 1000;
    const duration = parseFloat(this.getAttribute('dur') || '1') * 1000;

    this.subscription = fromEvent(document, this.getAttribute('trigger'))
      .pipe(
        delay(delayMs),
        switchMap(() => {
          const animation = target.animate(
            [{ opacity: 0 }, { opacity: 1 }],
            { duration, fill: 'forwards' }
          );
          return fromEvent(animation, 'finish');
        })
      )
      .subscribe(() => {
        this.dispatchEvent(new CustomEvent('anim-end'));
      });
  }

  disconnectedCallback() {
    if (this.subscription) {
      this.subscription.unsubscribe();
    }
  }
}
customElements.define('rx-animate', RxAnimateComponent);

Advantages of the Hybrid Approach

Replicating SMIL timing with Web Components and RxJS separates scheduling logic from visual rendering. Web Components maintain the readable, declarative structure that made SMIL popular for SVG authors, while RxJS eliminates the edge cases, memory leaks, and synchronization bugs traditionally associated with imperative animation code. Furthermore, wrapping subscriptions within element lifecycles ensures automatic garbage collection whenever elements are detached from the DOM.
