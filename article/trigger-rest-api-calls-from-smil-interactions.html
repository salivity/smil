Trigger REST API Calls from SMIL Interactions

This article explains how to trigger external REST API calls from user interactions within a SMIL (Synchronized Multimedia Integration Language) presentation. By utilizing SMIL 3.0 State Submission modules or interactive anchor triggers, developers can link user touch or click events directly to external HTTP endpoints, enabling digital signage and multimedia displays to communicate with third-party web services in real time.

The SMIL Submission Architecture

In modern SMIL implementations—particularly within interactive digital signage profiles—HTTP requests such as GET, POST, and PUT are handled using the SMIL State Submission module. This separates the definition of the REST endpoint from the visual element and user interaction.

The implementation consists of two core components:

  1. <submission>: Defined inside the <head> section, this element specifies the target URL, HTTP method, and response handling.
  2. <send>: Declared inside the <body> section, this element listens for a user interaction event (such as activateEvent or click) on a designated media element and executes the referenced <submission>.

Syntax and Implementation

Below is the standard syntax for executing a POST request to an external REST endpoint when a user taps or clicks an on-screen button.

<smil xmlns="http://www.w3.org/ns/SMIL" version="3.0" baseProfile="Language">
  <head>
    <layout>
      <root-layout width="1920" height="1080" backgroundColor="#000000" />
      <region id="mainRegion" left="0" top="0" width="1920" height="1080" />
      <region id="buttonRegion" left="810" top="900" width="300" height="100" />
    </layout>

    <!-- Define the REST API submission -->
    <submission id="callRestApi"
                action="https://api.example.com/v1/events"
                method="post"
                replace="none" />
  </head>
  <body>
    <par dur="indefinite">
      <!-- Background media -->
      <video src="background.mp4" region="mainRegion" repeatCount="indefinite" />

      <!-- Interactive target element -->
      <img id="triggerButton" src="button.png" region="buttonRegion" />

      <!-- Event listener that executes the submission on click -->
      <send submission="callRestApi" begin="triggerButton.activateEvent" />
    </par>
  </body>
</smil>

Attribute Breakdown

  • action: The absolute URL of the REST API endpoint.
  • method: The HTTP verb. Supported methods typically include post, get, and put.
  • replace: Controls how the application handles the server response. Setting this to "none" ensures the current SMIL presentation continues playing uninterrupted without reloading or navigating away.
  • begin="[elementId].activateEvent": Listens for the user activation (touch, click, or key press) on the specified element ID. Alternatively, begin="[elementId].click" can be used depending on the specific SMIL media player engine.

Alternative Syntax Using Interactive Anchors

For basic GET requests where complex submission attributes are not supported by the hardware player, the standard <a> element can execute a web call via interaction:

<a href="https://api.example.com/v1/trigger?action=checkin" external="true">
  <img id="simpleButton" src="button.png" region="buttonRegion" />
</a>

Using external="true" instructs the SMIL player to dispatch the HTTP request in the background rather than attempting to render the response inside the layout.
