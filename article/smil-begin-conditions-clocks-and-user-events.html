SMIL Begin Conditions: Clocks and User Events

Synchronized Multimedia Integration Language (SMIL) evaluates compound begin conditions combining clock-based values and user events by utilizing an instance time list governed by logical disjunction and dynamic interval resolution. Clock-based specifications produce static or sync-dependent instance times at timeline initialization, while interactive user events dynamically append new instance times whenever triggered. SMIL treats multiple conditions defined within a begin attribute as independent, alternative triggers, continuously evaluating the earliest valid begin time against the element's current active state and restart rules.

Semicolon-Separated Conditions and Disjunctive Evaluation

In SMIL, defining compound triggers in a begin attribute involves providing a semicolon-separated list of timing values, such as begin="5s; triggerButton.click". SMIL evaluates this list using logical OR semantics. The element does not wait for both a specific clock time and an interactive event to occur simultaneously; instead, satisfying any single condition in the list is sufficient to trigger the element. Each component—whether a clock-based offset, syncbase reference, or interactive event—operates as an autonomous potential trigger.

The Instance Time List Model

The SMIL timing engine processes compound conditions through a central construct called the begin instance list:

  1. Clock Values and Syncbases: Clocks (such as absolute offsets like 10s or syncbases like video.begin+2s) resolve during the document's initial timeline compilation or whenever the referenced element resolves its own intervals. These generate predetermined instance times in the list.
  2. User Events: Events (such as click, activate, or mouseover) cannot be predicted at compile time. When a user fires an event, the timing engine captures the current presentation time, adds any defined event offsets (such as button.click+1s), and dynamically inserts this new instance time into the sorted begin instance list.

Interval Calculation and Current Active State

Once an instance time enters the list—whether through clock progression or user interaction—the SMIL engine evaluates whether to create an active interval. The engine compares the newly available begin instance against the element's current state:

  • If the element is currently inactive, the engine selects the earliest valid instance time that occurs at or after the current presentation time and transitions the element to active.
  • If a user event produces an instance time that occurs earlier than a scheduled future clock trigger, the dynamic event takes precedence, causing the element to begin earlier than originally planned.

The Impact of the Restart Attribute

When combining static clocks with unpredictable user events, the restart attribute controls how subsequent triggers are handled:

  • restart="always": If an event fires or a clock condition resolves while the element is playing, the current active interval ends immediately and a new interval starts at that instance time.
  • restart="whenNotActive": If an event occurs while the element is active, the engine ignores the resulting instance time, preventing interruption until the current playback interval completes.
  • restart="never": The element responds only to the very first resolved condition (whether clock or event) and ignores all subsequent triggers for the remainder of the parent time container's life cycle.

Through this decoupled instance list and interval evaluation algorithm, SMIL harmonizes predictable, clock-driven timelines with nondeterministic, user-driven events.
