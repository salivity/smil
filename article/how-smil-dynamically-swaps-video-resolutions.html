How SMIL Dynamically Swaps Video Resolutions

This article details the mechanism behind dynamically swapping video resolutions in Synchronized Multimedia Integration Language (SMIL) based on fluctuating network speeds. It explores how client-side bandwidth detection, the SMIL <switch> element, bitrate threshold attributes, and keyframe alignment work together to deliver uninterrupted adaptive bitrate streaming.

The SMIL <switch> Element

The foundation of dynamic stream switching in SMIL is the <switch> element. The <switch> tag allows authors to define multiple alternative media elements, instructing the media player to evaluate constraints and select the single best child element to play at any given moment.

Inside the <switch> block, multiple video streams of the same content are declared, each encoded at different resolutions, frame rates, and bitrates.

<smil>
  <body>
    <switch>
      <video src="video_1080p.mp4" systemBitrate="4500000" width="1920" height="1080" />
      <video src="video_720p.mp4"  systemBitrate="2500000" width="1280" height="720" />
      <video src="video_480p.mp4"  systemBitrate="1000000" width="854"  height="480" />
      <video src="video_360p.mp4"  systemBitrate="500000"  width="640"  height="360" />
    </switch>
  </body>
</smil>

The systemBitrate Test Attribute

Dynamic adaptation relies on the systemBitrate attribute assigned to each <video> node. This attribute defines the estimated bandwidth, expressed in bits per second, required to deliver that specific stream smoothly.

When evaluating the <switch> block, the player processes the choices from top to bottom. It compares the current available bandwidth against the systemBitrate value of each stream. The player selects the highest-bitrate stream that does not exceed the currently measured network throughput.

Bandwidth Monitoring and Heuristics

The dynamic swapping process requires constant measurement of the client's network environment:

  1. Throughput Calculation: The media client continuously calculates the download rate of incoming media packets or video segments.
  2. Buffer Fill Rate: The client monitors the player buffer (measured in seconds of cached video). If the buffer drains faster than it fills, bandwidth has degraded. If the buffer remains full, spare bandwidth is available.
  3. Threshold Assessment: When network speed changes significantly, the client re-evaluates the systemBitrate conditions defined in the SMIL file to determine if a transition to a higher or lower resolution is required.

Seamless Switching at Keyframe Boundaries

Changing video resolutions mid-stream without causing playback stutter, visual artifacts, or audio desynchronization requires strict encoding and playback synchronization:

  • Aligned Keyframes (GOP Alignment): All alternative video streams must be encoded with identical Group of Pictures (GOP) structures and matching keyframe (I-frame) intervals.
  • Shared Timelines: Each resolution variant must share the same presentation timestamps (PTS).
  • Execution of the Switch: When a switch condition is met, the player does not change resolutions immediately. Instead, it waits for the next incoming keyframe boundary. At this exact synchronization point, the decoder seamlessly substitutes the video stream for the new resolution while keeping the audio stream continuous and uninterrupted.
