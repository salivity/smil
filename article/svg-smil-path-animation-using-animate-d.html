SVG SMIL Path Animation: Using animate d

This article provides an overview of how Scalable Vector Graphics (SVG) leverages Synchronized Multimedia Integration Language (SMIL) to animate complex shapes. It details how the <animate> element modifies the path data (d) attribute, the strict structural rules required for seamless shape morphing, key timing attributes, and how browsers compute vector interpolation natively without external JavaScript libraries.

How SMIL Path Morphing Works

In SVG, the <path> element defines custom vector shapes through its d (data) attribute, which contains a series of path commands (such as M for moveto, L for lineto, and C for curveto) followed by coordinate pairs.

To animate this attribute using SMIL, an <animate> element is nested inside the <path>. By setting the attributeName property to "d", the SVG user agent continuously interpolates the numerical coordinate values over time, creating a morphing effect between distinct shapes.

<svg viewBox="0 0 100 100" width="200" height="200">
  <path fill="teal" d="M 10 10 L 90 10 L 90 90 L 10 90 Z">
    <animate 
      attributeName="d" 
      dur="2s" 
      repeatCount="indefinite"
      to="M 50 10 L 90 90 L 50 70 L 10 90 Z" />
  </path>
</svg>

The Topology Matching Requirement

The critical rule governing path animation in SMIL is structural parity. A browser cannot automatically generate or remove vector control points during a transition. For smooth interpolation to occur:

  1. Identical Command Sequences: The list of path commands must match exactly in order and type. For instance, if the starting path uses M ... C ... C ... Z, the destination path must also use M ... C ... C ... Z.
  2. Matching Coordinate Counts: Each command must contain the exact same number of arguments. You cannot interpolate directly between a straight line (L, two values) and a cubic Bézier curve (C, six values).
  3. Identical Subpath Structures: Both states must contain the same number of subpaths and closepath (Z/z) commands.

If the command counts, types, or segment orders differ between the source and target states, the browser fails to interpolate. Instead, it falls back to a discrete jump, switching abruptly to the new shape at the halfway mark or end of the duration.

To morph between shapes with differing visual structures—such as a triangle and a circle—designers must normalize the paths. For example, a triangle must be constructed using Bézier curves with flat handles so that its point count matches the circle's control points.

Key Attributes for <animate d="...">

Several attributes control the mechanics of the path animation:

  • attributeName="d": Targets the path definition string for animation.
  • from and to: Defines the start and end path strings for a simple two-state transition.
  • values: A semicolon-separated list of path states used for multi-step animations (e.g., values="path1; path2; path3; path1").
  • dur: Specifies the clock duration for one cycle of the animation (e.g., 3s, 500ms).
  • repeatCount: Controls playback repetition, accepting a numeric value or "indefinite".
  • calcMode: Dictates how intermediate points are calculated:
    • linear (default): Interpolates coordinates at an even pace between keyframes.
    • paced: Calculates interpolation to produce an even speed across the entire animation, though rarely used with d due to computational complexity.
    • spline: Uses cubic Bézier timing curves defined by the keySplines attribute to simulate easing (e.g., ease-in, ease-out).
    • discrete: Jumps from one path state to the next with no smooth transition.
  • keyTimes: A semicolon-delimited list of normalized time values (ranging from 0 to 1) that dictates when each path in the values list should be reached.

Performance and Browser Execution

SMIL animations of the d attribute are processed natively by the browser's rendering engine. During each frame of the animation cycle:

  1. The renderer parses the numeric values associated with each command in the path string.
  2. It linearly calculates the delta for each coordinate pair based on elapsed time and easing settings.
  3. It constructs a temporary path in memory and rasterizes the new shape to the screen.

Because SMIL runs directly within the SVG DOM, animations persist when SVGs are embedded via <img> tags or used as CSS background images, scenarios where external JavaScript morphing engines (like GreenSock or anime.js) cannot execute.
