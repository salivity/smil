SMIL Animation Accumulation in Continuous SVG Rotation

Synchronized Multimedia Integration Language (SMIL) manages continuous transformations in SVG through dedicated accumulation and addition attributes that determine how values build over time. When creating an ongoing rotation, SMIL evaluates whether each repeated cycle resets the transform matrix or stacks progressively on the previous cycle's final value. Understanding the interplay between the accumulate and additive attributes provides precise control over angular velocity, transform list composition, and visual continuity in SVG graphics.

The Role of accumulate in Repeated Animations

In SMIL, the accumulate attribute controls whether an animation's value resets or adds up across iterations when repeatCount or repeatDur is defined. The attribute accepts two values:

  • accumulate="none" (default): Each repetition restarts strictly from the initial state defined in the from or values attribute. In a standard continuous 360-degree rotation, the cycle terminates at 360 degrees and immediately snaps back to 0 degrees to begin the next iteration. Because 0 degrees and 360 degrees represent identical geometric orientations, the visual motion appears seamless, but the underlying transform value resets every cycle.
  • accumulate="sum": Each subsequent cycle builds upon the end value of the previous cycle. If a rotation is set from 0 to 360, the first cycle spans \(0^\circ \to 360^\circ\), the second spans \(360^\circ \to 720^\circ\), the third spans \(720^\circ \to 1080^\circ\), and so on.

Interaction Between accumulate and <animateTransform>

When animating rotation via the <animateTransform type="rotate"> element, values consist of up to three parameters: rotation angle, center-x, and center-y (angle [cx cy]).

When accumulate="sum" is used:

  1. Angular Accumulation: SMIL uses component-wise addition. For the angle component, each cycle increments by the delta between the start and end values. If the animation rotates from 0 to 90 with four iterations, the object progressively shifts through \(0^\circ \to 90^\circ\), \(90^\circ \to 180^\circ\), \(180^\circ \to 270^\circ\), and \(270^\circ \to 360^\circ\).
  2. Center Coordinates: If rotation centers cx and cy are specified, accumulation applies to them as well if they change between the start and end states. To keep the element pivoting around a fixed point, the center coordinates must remain identical across the keyframes (e.g., from="0 50 50" to="360 50 50"). If the end coordinates differ from the start, the pivot point itself will shift continuously with every loop.

Distinguishing accumulate from additive

It is common to conflate accumulate with additive. While both handle value aggregation, they target different operational scopes:

  • additive: Governs how the animation combines with the element's underlying base transform attribute (or other preceding active animations). Setting additive="sum" appends the current rotation matrix to the existing transform list rather than overwriting it (additive="replace").
  • accumulate: Governs exclusively how repetitions within the same animation build upon preceding loops.

For continuous rotation overlaid on existing position coordinates, developers typically combine additive="sum" (to preserve preexisting SVG translations or scales) with accumulate="none" (for standard modular rotations) or accumulate="sum" (for continuously increasing numerical rotation states).
