SMIL Drop-Frame vs Non-Drop-Frame Timecodes

This article provides an overview of how the Synchronized Multimedia Integration Language (SMIL) timing model interprets and resolves drop-frame and non-drop-frame timecodes. It outlines the structural differences between these two SMPTE timecode formats, explains how SMIL translates discrete frame counts into continuous presentation time, and highlights how the parser prevents temporal drift when synchronizing fractional frame-rate media such as 29.97 fps video.

SMIL Clock Metrics and SMPTE Syntax

The SMIL timing model relies on a unified timeline where all synchronization elements—such as begin, dur, and end—resolve to absolute presentation times. While standard SMIL clock values use metric units like hours, minutes, seconds, and fractions (hh:mm:ss.fraction or timecount values like 120s), the SMIL specification also accommodates Society of Motion Picture and Television Engineers (SMPTE) timecodes.

SMPTE timecodes are specified within SMIL using explicit metric qualifiers, such as smpte:, smpte-25:, smpte-30:, and smpte-30-drop:. When a SMIL player encounters an SMPTE metric, it must convert discrete frame notation (hours:minutes:seconds:frames) into continuous floating-point seconds on the active presentation timeline.

Non-Drop-Frame (NDF) Handling in SMIL

Non-drop-frame timecodes are referenced using metrics such as smpte or smpte-30. In an NDF implementation, the timecode counts frames consecutively without skipping any numerical labels:

\[\text{Total Frames} = ((\text{hours} \times 3600) + (\text{minutes} \times 60) + \text{seconds}) \times \text{nominal\_fps} + \text{frames}\]

When applied to 30 fps nominal video playing at the true NTSC rate of approximately 29.97 fps (30000/1001 fps), this unbroken numerical progression introduces a timing discrepancy between the label and real-world wall-clock time. Over one hour of playback, an NDF counter accumulates a drift of approximately 3.6 seconds (108 frames) behind real elapsed time.

The SMIL engine handles NDF by mapping each frame duration to a fixed fractional interval defined by the specified timebase. If the SMIL context binds smpte-30 to 29.97 fps media, the engine calculates presentation time strictly based on cumulative frame counts. Consequently, event offsets keyed to NDF markers reflect media-relative position rather than wall-clock synchronization.

Drop-Frame (DF) Handling in SMIL

Drop-frame timecodes are identified in SMIL by the smpte-30-drop metric. Drop-frame timecode does not discard actual video frames; instead, it periodically drops frame numbers from the counter to maintain synchronization with real-world time.

In the standard SMPTE drop-frame algorithm:

  • Frame numbers 00 and 01 are omitted from the first second of every minute.
  • An exception is made for every tenth minute (minutes 00, 10, 20, 30, 40, and 50), where no frame numbers are dropped.

When a SMIL processor parses an smpte-30-drop value, it executes a conversion formula that accounts for the skipped labels before converting to seconds:

  1. Compute elapsed nominal minutes: \(M = \text{hours} \times 60 + \text{minutes}\)
  2. Calculate the number of dropped frame indices: \[\text{Dropped Frame Count} = 2 \times (M - \lfloor M / 10 \rfloor)\]
  3. Determine the real frame index: \[\text{Real Frame Index} = \text{Calculated Nominal Frames} - \text{Dropped Frame Count}\]
  4. Convert the real frame index to presentation time: \[\text{Presentation Time (seconds)} = \text{Real Frame Index} \times \frac{1001}{30000}\]

This adjustment ensures that a marker such as begin="smpte-30-drop:01:00:00:00" aligns precisely with 3600.0 seconds of wall-clock presentation time rather than drifting.

Timeline Normalization and Event Evaluation

Internally, SMIL does not preserve the native formatting of SMPTE timecodes during runtime evaluation. Instead, the timing engine immediately normalizes both drop-frame and non-drop-frame strings into a single double-precision continuous timeline (Document Time).

Because of this internal normalization:

  • Interoperability: Elements designated with smpte-30-drop can coexist seamlessly with elements designated in standard clock seconds (10s) or NDF markers.
  • Synchronization Graphs: The SMIL dependency graph resolves all interval begin and end conditions against a common numerical baseline, ensuring that parallel (<par>) and sequential (<seq>) containers execute correctly regardless of the source timecode convention used by the author.
