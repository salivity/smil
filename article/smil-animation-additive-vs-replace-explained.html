SMIL Animation: Additive vs Replace Explained

This article explores the core differences between additive (additive="sum") and replace (additive="replace") animations in SMIL (Synchronized Multimedia Integration Language) for SVG. You will learn how the additive attribute dictates whether an animation overwrites an element's existing properties or builds upon them, enabling predictable layering and complex multi-animation effects.

Understanding the additive Attribute

In SMIL, the additive attribute defines how an animation interacts with an element’s base value or with other animations concurrently modifying the same attribute. It accepts two primary values:

  • replace (the default behavior)
  • sum

Replace Animation (additive="replace")

When an animation uses additive="replace", it completely ignores the underlying attribute value while running. The animation treats its specified keyframes, from, to, or by values as absolute replacements for the target attribute.

  • Default State: If you omit the additive attribute entirely, SMIL assumes replace.
  • Base Value Handling: The original base attribute defined in the SVG markup is suppressed during playback.
  • Multiple Animations: If two or more animations target the same attribute with additive="replace", the one that started most recently or has the highest priority will overwrite the others.

Example Scenario

If a circle has a base radius r="20" and an animation runs from="30" to="50" with additive="replace", the circle starts at radius 30 and expands to 50. The initial radius of 20 has no mathematical impact on the animation.

Additive Animation (additive="sum")

When an animation uses additive="sum", its calculated value is mathematically added to the base value of the attribute, or to the result of any underlying animations targeting that same attribute.

  • Relative Transformation: The animation acts as an offset rather than an absolute value.
  • Stacking and Layering: Multiple animations can run simultaneously on the same attribute without conflicting, accumulating their effects together.

Example Scenario

If a circle has a base radius r="20" and an animation runs from="0" to="30" with additive="sum", the resulting radius animates from 20 (20 + 0) up to 50 (20 + 30).

Key Differences at a Glance

Feature additive="replace" additive="sum"
Default Behavior Yes (implicit if omitted) No (must be explicitly declared)
Base Value Impact Discards/overwrites the base value Adds animated offsets onto the base value
Animation Stacking Overrides previous animations Combines with previous animations
Primary Use Case Absolute transitions (e.g., color shifts, direct repositions) Combined transforms (e.g., rotating while scaling, multiple movement paths)

Working with <animateTransform>

The distinction between replace and sum is especially critical when using <animateTransform>.

Because standard SVG transforms (like rotate, scale, and translate) share the single transform attribute, using additive="replace" causes any subsequent transform animation to cancel out earlier ones. Setting additive="sum" allows you to stack a rotation, a translation, and a scale animation onto the same element simultaneously without each operation wiping out the others.
