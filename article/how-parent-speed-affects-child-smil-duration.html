How Parent Speed Affects Child SMIL Duration

This article explores how a parent container's speed attribute influences child elements in the Synchronized Multimedia Integration Language (SMIL) timing model. It breaks down the interaction between container-level speed transformations and element durations, clarifying the distinction between a child's intrinsic simple duration in its local timeline and its effective active duration mapped onto the parent's timeline.

The SMIL Local Time System

In the SMIL specification, timing relationships are hierarchical. Every time container—such as <par>, <seq>, or <excl>—defines a local time coordinate system for its direct children. Elements within that container evaluate their beginning, end, and duration relative to this local clock rather than the global document timeline.

Invariance of the Simple Duration

A parent container’s speed transformation does not alter the declared simple duration (dur) of a child element.

The simple duration is an intrinsic property defined entirely in the child element's local time coordinate system. For example, if a child specifies dur="10s", its simple duration remains precisely 10 seconds of element time. The child must progress through 10 units of its internal timeline from start to finish, regardless of what happens higher up in the document tree.

Clock Rate Scaling

While the simple duration remains constant in element time, the parent container's speed attribute determines the rate at which element time elapses relative to parent time.

The relationship between the progression of parent time (\(t_{parent}\)) and child time (\(t_{child}\)) is defined by the transformation rate:

\[\Delta t_{child} = \Delta t_{parent} \times \text{speed}\]

  • Speed greater than 1.0 (Acceleration): If the parent container specifies speed="2.0", the local clock of the child runs twice as fast as the parent clock. The child still experiences 10 seconds of internal simple duration, but it completes that duration in only 5 seconds of parent time.
  • Speed between 0.0 and 1.0 (Deceleration): If the parent container specifies speed="0.5", the child's local clock advances at half-speed. The 10-second simple duration requires 20 seconds of parent time to finish.
  • Negative Speed (Reverse Playback): If an implementation supports negative speed values (e.g., speed="-1.0"), the simple duration remains unchanged in magnitude, but the child plays backward within its simple duration window.

Effective Duration in the Parent Timeline

Because the rate of time passage changes, the child element's apparent or effective duration in the parent timeline (\(Dur_{effective}\)) is scaled inversely to the parent container's speed:

\[Dur_{effective} = \frac{dur_{child}}{\text{speed}_{parent}}\]

This scaling cascades into the child's active duration calculations. If a child defines repetitions (repeatCount or repeatDur), each cycle still respects the unmodified simple duration locally, while each cycle completes in scaled time relative to the parent.

Nested Speed Transformations

When time containers are nested, speed transformations compound multiplicatively. If a top-level container has speed="2.0" and an inner container has speed="1.5", any child inside the inner container has an effective speed of 3.0 relative to the document clock. The child's simple duration is still preserved locally, but its elapsed playback time in document coordinate space is compressed by a factor of three.
