Combining Multiple SVG animateTransform Elements

In SVG SMIL animations, the <animateTransform> element modifies a target element's transform attribute using operations like translate, scale, and rotate. Because the default SMIL behavior replaces previous transformations rather than merging them, combining multiple transformation types requires specific configurations. This article explains how SMIL handles simultaneous transformations through the additive attribute and matrix order, as well as the alternative nested group technique for complex animations.

The Default Overwrite Behavior

By default, an <animateTransform> element has its additive attribute set to replace. When multiple <animateTransform> elements target the same element concurrently—such as one attempting to translate and another attempting to rotate—the animation defined last in the document will overwrite the preceding ones. Consequently, the element will not display a combined effect, but rather only the final active transform.

Using additive="sum"

To combine translation, rotation, and scaling on a single element, you must explicitly declare additive="sum" on the secondary (and subsequent) <animateTransform> elements, and preferably on all of them.

<rect width="50" height="50" fill="royalblue">
  <!-- Translation -->
  <animateTransform 
    attributeName="transform" 
    type="translate" 
    from="0,0" to="100,50" 
    dur="4s" repeatCount="indefinite" 
    additive="sum" />

  <!-- Rotation -->
  <animateTransform 
    attributeName="transform" 
    type="rotate" 
    from="0 25 25" to="360 25 25" 
    dur="4s" repeatCount="indefinite" 
    additive="sum" />

  <!-- Scaling -->
  <animateTransform 
    attributeName="transform" 
    type="scale" 
    values="1; 1.5; 1" 
    dur="4s" repeatCount="indefinite" 
    additive="sum" />
</rect>

When additive="sum" is used, the transformation matrices generated by each animation are post-multiplied together.

Transformation Order Matters

In matrix mathematics, transformation order dictates the visual outcome. For instance, rotating an object and then translating it produces a different trajectory than translating it first and then rotating it around its own center.

In SMIL, when multiple <animateTransform> elements with additive="sum" are applied to the same element, they are processed in document order. The first <animateTransform> listed forms the base matrix, and each subsequent <animateTransform> post-multiplies its matrix onto the running total:

\[\text{Final Transform} = M_1 \times M_2 \times M_3\]

If your translate animation precedes your rotate animation, the object moves first and then rotates around the specified origin. If the rotate animation is placed first, translation moves the object along the rotated axes.

The Nested Group Technique

While additive="sum" works directly on a single element, managing multiple transformations and their relative origins can become complex. An alternative approach is nesting SVG <g> (group) elements, assigning a single <animateTransform> to each group:

<g>
  <animateTransform 
    attributeName="transform" 
    type="translate" 
    from="0 0" to="100 50" 
    dur="4s" repeatCount="indefinite" />
  
  <g>
    <animateTransform 
      attributeName="transform" 
      type="rotate" 
      from="0 25 25" to="360 25 25" 
      dur="4s" repeatCount="indefinite" />

    <g>
      <animateTransform 
        attributeName="transform" 
        type="scale" 
        values="1; 1.5; 1" 
        dur="4s" repeatCount="indefinite" />

      <rect width="50" height="50" fill="royalblue" />
    </g>
  </g>
</g>

This method eliminates the need for additive="sum" because each transform operates in its own local coordinate system. It provides clear, hierarchical control over the exact order in which translation, scaling, and rotation are evaluated.
