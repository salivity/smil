SMIL Coordinate Systems in Nested Regions

This article provides an overview of how the Synchronized Multimedia Integration Language (SMIL) establishes and calculates coordinate systems for nested layout regions. In SMIL, visual layouts rely on a hierarchical model where child regions derive their positioning context directly from their immediate parent containers. Understanding how origin points, dimensional units, and boundary offsets operate within these nested elements is essential for creating flexible, structured multimedia presentations.

The Parent-Child Hierarchy

SMIL 2.0 and later versions support hierarchical layout through the nesting of <region> elements inside other <region> elements or within a <topLayout>. The top-level container defines the global presentation window, establishing the root coordinate space.

When a <region> is nested inside an existing region, the inner region becomes a child of the outer region. Rather than referencing the global viewport, the nested region calculates all geometric placement solely within the bounding box of its immediate parent.

The Local Origin Point

The coordinate system of any nested region begins with an origin point of (0, 0) located at the upper-left corner of its immediate parent region's boundary.

Any movement along the horizontal X-axis increases positively to the right of this origin, while movement along the vertical Y-axis increases positively downward. Because the origin is bound to the parent's upper-left corner, moving or resizing the parent region automatically shifts the entire coordinate space—and consequently the visual placement—of all nested child regions.

Positioning Attributes and Offsets

SMIL defines region placement using four primary directional attributes alongside standard dimensions:

  • left: Specifies the horizontal distance from the parent’s left edge to the child’s left edge.
  • top: Specifies the vertical distance from the parent’s top edge to the child’s top edge.
  • right: Specifies the horizontal distance inward from the parent’s right edge to the child’s right edge.
  • bottom: Specifies the vertical distance inward from the parent’s bottom edge to the child’s bottom edge.
  • width and height: Define the explicit dimensions of the child region.

If a developer defines left and right without explicitly specifying a width, the SMIL player calculates the child region's width based on the remaining space between those two boundaries relative to the parent’s total width. The vertical dimension operates identically when using top and bottom without an explicit height.

Units of Measurement

Nested coordinate systems accept both absolute and relative units:

  • Pixel Values: Fixed numbers (e.g., 50px or a unitless integer) define static offsets. An offset of left="50" positions the child region exactly 50 pixels to the right of the parent’s left boundary, regardless of changes to the parent's overall size.
  • Percentage Values: Expressed with a percent sign (e.g., left="25%"), these values resolve dynamically against the width or height of the parent region. For instance, if a parent region is 400 pixels wide, a nested region with left="25%" and width="50%" results in an absolute left offset of 100 pixels and a width of 200 pixels.

Stacking Contexts and Clipping

In addition to horizontal and vertical coordinates, nested regions inherit the clipping and layering behavior of their parents.

If a nested region's dimensions exceed the boundary of its parent, the fit and overflow attributes of the parent determine whether the child content is clipped, scrolled, or visible outside the defined coordinate bounds. Depth positioning along the Z-axis is managed using the z-index attribute; nested regions can establish local stacking orders, ensuring that nested visual media renders in predictable layers relative to sibling elements within the same parent context.
