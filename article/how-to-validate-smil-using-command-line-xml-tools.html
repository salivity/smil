How to Validate SMIL Using Command-Line XML Tools

Synchronized Multimedia Integration Language (SMIL) is an XML-based markup language used for orchestrating multimedia presentations, common in DAISY talking books, EPUB 3 Media Overlays, and MMS messaging. Because SMIL is fundamentally XML, it can be tested for both structural well-formedness and schema compliance using automated command-line utilities. This guide demonstrates how to configure and execute automated SMIL validation using industry-standard tools like xmllint and xmlstarlet, along with integration strategies for continuous integration (CI) pipelines.

Prerequisites for SMIL Validation

Validating a SMIL file requires two checks:

  1. Well-Formedness: Ensuring the document adheres to basic XML syntax (e.g., properly closed tags, correct nesting, valid attribute syntax).
  2. Validity: Ensuring the document complies with a specific SMIL Document Type Definition (DTD) or XML Schema Definition (XSD), such as SMIL 3.0 or the EPUB 3 Media Overlays profile.

Before running automated validation, acquire the relevant .dtd or .xsd schema file corresponding to your SMIL version.

Validating SMIL with xmllint

xmllint is part of the libxml2 library and is pre-installed on most Unix-like operating systems. It is lightweight, fast, and ideal for automation scripts.

1. Check for Well-Formedness

To check if a SMIL file is structurally sound XML without validating against a schema:

xmllint --noout presentation.smil
  • --noout: Suppresses the output of the parsed XML tree, only displaying parsing errors.
  • Returns an exit status code of 0 on success, or a non-zero code on failure.

2. Validate Against a DTD

If your SMIL document contains a valid <!DOCTYPE> declaration with an accessible system identifier, run:

xmllint --noout --valid presentation.smil

To validate against a local SMIL DTD file without relying on network fetching:

xmllint --noout --dtdvalid /path/to/smil.dtd --nonet presentation.smil
  • --dtdvalid: Points directly to the local DTD definition.
  • --nonet: Prevents network access for resolving external entities, ensuring consistent speed and reliability in isolated CI environments.

3. Validate Against an XML Schema (XSD)

If your implementation uses an XSD schema instead of a DTD:

xmllint --noout --schema /path/to/smil.xsd --nonet presentation.smil

Validating SMIL with xmlstarlet

xmlstarlet is another robust command-line toolkit optimized for shell-based XML operations.

1. Well-Formedness Check

xmlstarlet val -w presentation.smil

2. Schema Validation (XSD)

To validate a SMIL file against an XSD schema:

xmlstarlet val --err --xsd /path/to/smil.xsd presentation.smil
  • --err: Prints error messages directly to stderr.
  • --xsd: Specifies the path to the XML schema.

3. DTD Validation

xmlstarlet val --err --dtd /path/to/smil.dtd presentation.smil

Automating Batch Validation in Shell Scripts

To validate multiple SMIL files across a project directory, use the find command combined with xmllint:

#!/usr/bin/env bash
set -e

SCHEMA_PATH="./schemas/smil30.xsd"
SMIL_DIR="./media"

echo "Validating all SMIL files against $SCHEMA_PATH..."

find "$SMIL_DIR" -type f -name "*.smil" -exec xmllint --noout --schema "$SCHEMA_PATH" --nonet {} +

echo "All SMIL files are valid."

If any SMIL file fails validation, xmllint will output the line and column number along with the error description, and the script will terminate with a non-zero exit code due to set -e.

Integrating into CI/CD Pipelines

Automated linters integrate directly into CI systems like GitHub Actions or GitLab CI.

Example: GitHub Actions Workflow Step

name: Validate SMIL Assets

on: [push, pull_request]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Install libxml2-utils
        run: sudo apt-get update && sudo apt-get install -y libxml2-utils

      - name: Validate SMIL Files
        run: |
          find . -name "*.smil" -print0 | xargs -0 -n 1 xmllint --noout --schema ./schemas/smil.xsd --nonet

This configuration ensures that every pull request or commit containing invalid SMIL structure or schema violations fails the build before deployment.
