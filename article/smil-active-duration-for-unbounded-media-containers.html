SMIL Active Duration for Unbounded Media Containers

This article explains how the Synchronized Multimedia Integration Language (SMIL) calculates the active duration of time containers (<par>, <seq>, and <excl>) containing unbounded or indefinite child media. It breaks down the interaction between implicit durations, explicit timing attributes, container-specific rules, and the endsync attribute to illustrate how the SMIL timing model resolves media with no predetermined end.

Understanding Unbounded Child Media

In SMIL, unbounded child media refers to elements whose simple or active durations cannot be known in advance. This commonly includes continuous live streams, media with dur="indefinite", or interactive elements that wait indefinitely for user input. Because these elements have no inherent end time, the container holding them must rely on standard resolution algorithms to determine its own active duration.

Step 1: Determining the Implicit Duration

Before a container computes its active duration, it must establish its implicit duration based on its children and the container type:

  • Parallel Containers (<par>): The implicit duration depends on the endsync attribute. By default, endsync="last", meaning the container's implicit duration continues until all children have ended. If at least one child is unbounded and never ends, the container's implicit duration is resolved as indefinite. Conversely, if endsync="first" is declared, the implicit duration ends as soon as the first finite child finishes, regardless of any unbounded siblings.
  • Sequential Containers (<seq>): A sequence plays elements one after another. If an unbounded child begins playing, subsequent elements are blocked from starting. Unless interrupted by an outside condition, the implicit duration of the sequence becomes indefinite because the unbounded element never reaches its natural end.
  • Exclusive Containers (<excl>): Similar to <par>, an <excl> container pauses or stops inactive children while one child plays. Its implicit duration relies on endsync="last" by default, which resolves to indefinite if an active child runs indefinitely without another element preempting it.

Step 2: Calculating the Simple Duration

The simple duration (\(dur\)) of the container is resolved by comparing its implicit duration against any explicitly authored duration:

  1. If an explicit dur attribute is defined on the container (e.g., dur="30s"), the simple duration is strictly set to that explicit value, truncating the unbounded child when the time expires.
  2. If dur="indefinite" is explicitly assigned, the simple duration is indefinite.
  3. If no dur attribute is specified, the simple duration equals the implicit duration calculated in Step 1. If that implicit duration is indefinite, the simple duration remains indefinite.

Step 3: Computing the Active Duration

Once the simple duration is resolved, SMIL computes the active duration by applying repetition, bounds, and ending constraints:

  • Repetition (repeatCount and repeatDur): If the simple duration is indefinite, repetition attributes cannot compute multiple cycles based on simple boundaries. The active duration remains indefinite.
  • Explicit end Attributes: If the container defines an explicit end attribute (such as a specific clock value or an external event), this serves as an overriding hard boundary. When the end condition occurs, the container's active duration terminates immediately, ending playback of any unbounded child media.
  • Min and Max Constraints (min / max):
    • If the calculated active duration is indefinite, but an explicit max constraint is set (e.g., max="60s"), the active duration is capped at the max value.
    • If a min value is set, the active duration cannot end before that threshold, though this primarily affects early-terminating media rather than unbounded elements.

Summary Rule

When a SMIL container holds unbounded child media, its active duration resolves to indefinite by default (under standard endsync="last" conditions). It will play indefinitely unless an author explicitly bounds the container using a specified dur, an overriding end condition, an endsync="first" rule, or a max constraint.
