Understanding SMIL Wallclock Time: Local vs UTC

In Synchronized Multimedia Integration Language (SMIL), scheduling multimedia elements can be tied to real-world time rather than presentation-relative timelines by using the wallclock() syntax. SMIL relies on a subset of the ISO 8601 standard to parse these date and time representations. The language distinguishes between local wallclock time and Coordinated Universal Time (UTC) strictly through the presence or absence of a Time Zone Designator (TZD) at the end of the time string.

The wallclock() Value Syntax

SMIL allows timing attributes such as begin and end to take a wallclock value formatted as wallclock(date-time). The date component follows the YYYY-MM-DD pattern, followed by the delimiter T, and ends with the time component hh:mm:ss (optionally including fractional seconds). Alternatively, wallclock values can specify a time-of-day without a date component, such as wallclock(hh:mm:ss).

Specifying Local Wallclock Time

Local wallclock time is defined by omitting the Time Zone Designator entirely. When a SMIL presentation engine parses a wallclock string without a timezone indicator, it interprets the value relative to the local system clock and timezone settings of the host machine running the presentation.

  • Date and Time: begin="wallclock(2024-10-15T09:30:00)"
  • Time of Day Only: begin="wallclock(09:30:00)"

In both instances, the element triggers when the host system's internal clock reads 9:30 AM in the local environment, regardless of the user's geographic location or timezone offset from UTC.

Specifying UTC Wallclock Time

To explicitly designate UTC, SMIL requires the inclusion of the Z designator (indicating "Zulu" or zero offset) immediately following the time string. This instructs the rendering engine to evaluate the schedule against universal time rather than local system conventions.

  • Date and Time in UTC: begin="wallclock(2024-10-15T09:30:00Z)"
  • Time of Day in UTC: begin="wallclock(09:30:00Z)"

When using the Z identifier, a client machine located in Eastern Standard Time (UTC-5) will trigger the event at 4:30 AM local time, which corresponds directly to 9:30 AM UTC.

Specifying Explicit Offsets from UTC

SMIL also accommodates explicit timezone offsets relative to UTC using standard +hh:mm or -hh:mm suffixes. While these represent time in a designated geographic zone, they are evaluated against UTC mathematically.

  • Positive Offset (e.g., Central European Time): begin="wallclock(2024-10-15T10:30:00+01:00)"
  • Negative Offset (e.g., Eastern Daylight Time): begin="wallclock(2024-10-15T05:30:00-04:00)"

Both examples resolve to the exact same absolute timestamp as 2024-10-15T09:30:00Z.

Summary of Processing Rules

The SMIL processor determines temporal context through the following rules:

  1. No TZD appended: Handled entirely as local time based on the playback client's operating system.
  2. Z appended: Handled as absolute UTC.
  3. +hh:mm or -hh:mm appended: Converted directly to UTC by applying the designated offset to determine the absolute global point in time for playback.
