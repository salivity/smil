How SMIL Synchronizes MIDI with Vector Graphics

Synchronized Multimedia Integration Language (SMIL) coordinates the playback of MIDI sequences with vector graphics by utilizing a declarative, timeline-driven synchronization engine. By defining relationships through structured time containers, syncbase references, and event triggers, SMIL creates a unified temporal context where synthesized audio tracks and visual nodes—such as Scalable Vector Graphics (SVG)—execute concurrently, ensuring that visual transformations align precisely with musical notes, cues, and track durations.

The Unified Timeline and Time Containers

SMIL achieves synchronization by placing independent media components into structural timing containers, primarily the <par> (parallel) and <seq> (sequential) elements. When synchronizing a MIDI synthesizer playback with vector graphics:

  • Parallel Containers (<par>): Encapsulate both the MIDI asset (referenced via <audio> or <ref>) and the vector graphic elements. The <par> container establishes a common parent timeline, starting the audio playback and graphic animations at the exact same moment by default.
  • Sequential Containers (<seq>): Enforce strict chronological order, allowing vector animations to trigger in discrete phases as different MIDI tracks or sequence sections complete.

Syncbase Timing and Relative Offsets

Rather than relying on continuous procedural polling (such as requestAnimationFrame in JavaScript), SMIL relies on syncbase timing. Syncbase timing allows the begin or end attributes of a vector animation to reference the temporal state of the MIDI media object.

A vector transformation can declare its start time relative to the audio:

<par>
  <audio id="midiTrack" src="composition.mid" />
  <rect id="visualBox" width="100" height="100">
    <animate attributeName="x" from="0" to="300" dur="4s" begin="midiTrack.begin + 2s" />
  </rect>
</par>

In this architecture, the vector transformation calculates its start dynamically based on when the MIDI synthesizer is initialized and begins outputting sound, applying an exact two-second offset.

Media Markers and Event-Driven Synchronization

MIDI files often contain internal metadata, including tempo maps, bar markers, and cue points. SMIL engines that interface with system-level MIDI synthesizers map these markers to internal SMIL events:

  1. Marker Events: Vector animations can listen for specific marker points embedded inside the MIDI file using the syntax begin="midiTrack.marker(chorusStart)". When the MIDI sequencer hits the designated marker, the SMIL scheduler immediately fires the corresponding visual vector changes (such as color fills, path morphing, or scaling).
  2. Dynamic Clocks and Drift Correction: Synthetic audio and vector rendering run on separate sub-systems—the operating system's MIDI software/hardware synthesizer and the graphics rasterizer. SMIL implementations maintain synchronization across both by designating the audio track as the master clock (syncBehavior="locked"). If visual rendering stalls or drops frames due to processing constraints, the SMIL engine drops intermediate animation states to snap the vector graphics back in step with the ongoing MIDI timeline.

Direct Integration with SVG

Because SVG adopted the SMIL specification for its native animation elements (<animate>, <animateTransform>, <animateMotion>), synchronizing MIDI with vector scenes works seamlessly across the document object tree. The vector components modify their geometric coordinates, Bézier curves, or styling attributes strictly mapped against the progress of the MIDI track, enabling lightweight, low-bandwidth, and mathematically precise audiovisual presentations.
