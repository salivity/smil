How animateColor Interpolates SMIL Color Values

The <animateColor> element in SMIL interpolates color values over time by decomposing colors into distinct numeric color channels and calculating intermediate values mathematically for each frame. This article explains the underlying mechanics of this process, including channel extraction, mathematical interpolation formulas, calculation modes, and the influence of color space settings.

Color Channel Extraction and Parsing

Before interpolation can occur, <animateColor> parses the starting, ending, and intermediate values defined in attributes such as from, to, by, or values. Regardless of whether colors are declared as hex codes (#ff0000), named colors (red), or functional notation (rgb(255, 0, 0)), the rendering engine normalizes them into separate numerical channels: Red (R), Green (G), Blue (B), and Alpha (A).

Color components are typically converted to normalized floating-point numbers in the range [0.0, 1.0] or integers in the range [0, 255] before the animation engine performs calculations.

Channel-by-Channel Linear Interpolation

SMIL evaluates transitions using independent linear interpolation for each color channel. Given a normalized time progress \(t\) ranging from \(0\) to \(1\) between two keyframes, a channel value \(V\) transitions from a starting value \(V_0\) to an ending value \(V_1\) using the standard formula:

\[V(t) = V_0 \times (1 - t) + V_1 \times t\]

Because this calculation applies individually to R, G, B, and A channels, the resulting intermediate colors move in a straight line through the active Cartesian color space rather than traversing a perceptual color wheel (such as HSL).

Calculation Modes (calcMode)

The timing and progression of channel interpolation are directed by the calcMode attribute:

  • linear (default): Divides the animation time evenly across value segments, applying linear mathematical interpolation between adjacent values.
  • discrete: Disables interpolation entirely. The engine jumps instantly from one color to the next at specified time intervals without generating intermediate frames.
  • paced: Calculates the total Euclidean distance through the color space across all specified colors to maintain a constant speed of color change throughout the entire duration.
  • spline: Employs cubic Bézier curves defined by the keyTimes and keySplines attributes. The engine maps progress \(t\) through the spline function before computing the linear channel blend, enabling effects such as ease-in and ease-out transitions between colors.

Color Space Context

The visual output of the interpolation depends heavily on the color-interpolation property:

  • sRGB (default): Interpolation occurs directly on gamma-compressed sRGB channel values. While computationally lightweight, this can occasionally result in intermediate colors appearing darker or desaturated at midpoints.
  • linearRGB: The engine first linearizes gamma-encoded sRGB values, performs the channel interpolation in a linear radiometric space, and converts the result back to sRGB for screen rendering. This yields smoother, physically accurate color transitions that avoid muddy intermediate shades.

Although <animateColor> has been deprecated in modern SVG specifications in favor of the unified <animate> element, modern SVG engines continue to process color animations using these exact interpolation principles.
