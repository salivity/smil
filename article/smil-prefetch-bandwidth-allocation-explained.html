SMIL Prefetch Bandwidth Allocation Explained

In Synchronized Multimedia Integration Language (SMIL), the prefetch element optimizes multimedia playback by downloading media assets into the local cache before they are scheduled to play. This article explains how the prefetch element controls network consumption, specifically examining the bandwidth attribute, its syntax, and how user agents balance background downloads against foreground media playback to prevent buffering disruptions.

The primary mechanism for controlling download throughput within a prefetch element is the bandwidth attribute. This attribute instructs the SMIL presentation engine on how much network capacity it can dedicate to pre-fetching an asset while other media might be actively rendering. By setting boundaries on background transfer rates, authors prevent prefetch operations from starving active audio or video streams of required throughput.

The bandwidth attribute accepts values formatted either as absolute data rates or as relative percentages:

  • Absolute Rates: Defined using integers representing bits per second, often appended with unit identifiers such as bps, kbps, or Mbps (e.g., bandwidth="128kbps"). When an absolute value is set, the player limits the download stream to not exceed that specified ceiling, regardless of total network capacity.
  • Percentages: Defined using a numerical value followed by a percent sign (e.g., bandwidth="40%"). This assigns a proportional share of the remaining available bandwidth that is not currently consumed by active, time-critical presentation elements.

When configuring the prefetch element, the bandwidth attribute functions in tandem with two other resource-governing attributes: mediaSize and mediaTime. While bandwidth sets the speed of transfer, mediaSize limits the download by volume (in bytes or percentages of total file size), and mediaTime limits the download by playback duration (such as pre-buffering the first 10 seconds of a video).

A standard implementation in SMIL markup appears as follows:

<prefetch src="rtsp://example.com/video.mp4" 
          bandwidth="256kbps" 
          mediaTime="20s" />

During execution, the SMIL player evaluates the network requirements of active foreground streams. If overall network availability drops, the player throttles or temporarily suspends the prefetch task defined by the bandwidth setting, prioritizing the immediate presentation. Once sufficient overhead is detected, the background transfer resumes up to the configured bandwidth limit until the specified quantity of media is cached.
