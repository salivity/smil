SMIL Touch Events on Overlapping Transparent Regions

In Synchronized Multimedia Integration Language (SMIL), processing touch or pointer events across overlapping transparent media regions depends on the layout stacking order (z-index), the active sensitivity attribute, and spatial hit-testing rules. When multiple media layers occupy the same coordinate space, the SMIL runtime determines which element captures the touch based on visual depth and element responsiveness. By default, the topmost active element in the visual hierarchy intercepts the event, blocking underlying layers unless transparency and event pass-through are explicitly configured.

The Stacking Hierarchy and Z-Index

SMIL layout modules define screen placement using region elements within a layout container. When two or more regions overlap, their depth is governed by the z-index attribute:

  • Topmost Element Priority: The media element rendered with the highest z-index is evaluated first during hit-testing.
  • Default Tree Order: If z-index values are identical or omitted, the SMIL rendering engine evaluates elements in the order of document declaration (document tree order), with later elements rendered above earlier ones.

When a touch occurs at a point where multiple regions intersect, the coordinate is tested against the topmost layer first.

Transparency and the sensitivity Attribute

Visual transparency (an alpha channel of 0% or empty background regions) does not automatically permit touch events to fall through to lower layers. In SMIL:

  • Default Event Capture: A fully transparent media region will still intercept touch events if it is designated as interactive (e.g., waiting for an activateEvent) and has default sensitivity. This behavior effectively creates an invisible shield over the media beneath it.
  • The sensitivity Control: SMIL provides the sensitivity attribute to dictate how user input is registered relative to transparency:
    • Setting sensitivity="none" (or leveraging pointer-events: none in hybrid SVG/SMIL profiles) instructs the engine to ignore touches on that layer, routing the interaction down to the next underlying visible region.
    • Setting sensitivity="opaque" or defining alpha-channel thresholds ensures that only areas containing actual rendered pixels register input, allowing touches on transparent pixels to fall through.

Processing Simultaneous Touch Events

When handling true multi-touch inputs—where multiple touch points occur concurrently across overlapping regions—the engine processes each contact point independently:

  1. Point-by-Point Evaluation: Each touch contact is assigned a unique identifier and evaluated against the coordinate plane independently.
  2. Distinct Target Assignment: If Finger A touches a non-overlapping section of Region 1, and Finger B simultaneously touches an overlapping section of Region 1 and Region 2, the runtime resolves each point separately. Finger A triggers the interaction on Region 1, while Finger B targets whichever layer possesses topmost interactive priority at that specific coordinate.
  3. Single Contact Collisions: A single physical touch point cannot trigger two overlapping interactive media elements simultaneously. SMIL does not implement standard DOM-style spatial bubbling down the Z-axis. Once the topmost sensitive element claims the event (such as triggering an activateEvent), the interaction is consumed, and underlying layers remain unaffected.

Media State and Timing Constraints

SMIL is an inherently time-based language. Hit-testing is strictly bounded by the temporal lifecycle of the overlapping elements:

  • An overlapping region is only eligible to receive touch events during its active interval (between begin and end).
  • If a top-layer transparent element has reached its end time and is no longer active, the engine bypasses it entirely, passing incoming touch events directly to the now-exposed layer beneath it.
