Build Branching Quizzes with SMIL excl and Links

Synchronized Multimedia Integration Language (SMIL) offers robust declarative timing and layout mechanisms, enabling developers to build non-linear, interactive presentations without complex scripting. This article explains how to create branching multiple-choice quiz questions using the SMIL <excl> (exclusive) time container paired with interactive <a> links. By leveraging these elements, you can route users to distinct feedback screens or question paths based on their chosen answers while automatically halting conflicting media.

The Role of the <excl> Container

The <excl> container enforces mutual exclusivity among its child elements: only one child can play at any given moment. If a new child element is activated, the currently active child is either stopped or paused, depending on the container's configuration.

In a quiz context, this behavior is essential for feedback management. You can place the outcomes for every answer option inside an <excl> block. When a user selects an answer, only the corresponding response or branch plays, preventing overlapping visual cues or audio tracks.

Triggering Paths with Links

Interactivity in SMIL is achieved using the <a> tag or event-based timing attributes. For multiple-choice branching:

  1. Option Elements: Wrap your interactive options (text buttons, images, or clickable regions) with <a> elements.
  2. Targeting Destinations: Point the href attribute of each <a> tag to the unique id of the target outcome defined within the <excl> block, or use the begin="buttonId.activateEvent" syntax on the target elements.
  3. Standby State: Set the target elements inside the <excl> container to begin="indefinite", ensuring they remain inactive until the user triggers them.

Structural Architecture

A basic quiz structure nests the question assets and choices alongside the exclusive feedback container within a parallel (<par>) block.

<smil xmlns="http://www.w3.org/ns/SMIL">
  <body>
    <!-- Outer sequence for question progression -->
    <seq>
      <!-- Question 1 -->
      <par dur="indefinite">
        <!-- Display Question Prompt -->
        <text src="question1.txt" region="question_area" />

        <!-- Choice A: Correct Answer -->
        <a href="#feedbackCorrect">
          <text src="choiceA.txt" region="choice_a_area" />
        </a>

        <!-- Choice B: Incorrect Answer -->
        <a href="#feedbackIncorrect">
          <text src="choiceB.txt" region="choice_b_area" />
        </a>

        <!-- Exclusive container for mutually exclusive feedback -->
        <excl>
          <!-- Correct Path -->
          <par id="feedbackCorrect" begin="indefinite">
            <text src="correct.txt" region="feedback_area" dur="4s" />
            <audio src="cheer.mp3" dur="4s" />
          </par>

          <!-- Incorrect Path -->
          <par id="feedbackIncorrect" begin="indefinite">
            <text src="incorrect.txt" region="feedback_area" dur="4s" />
            <audio src="buzzer.mp3" dur="4s" />
          </par>
        </excl>
      </par>
      
      <!-- Question 2 (loads automatically after Question 1 resolves) -->
      <par dur="indefinite">
        <!-- Next question content -->
      </par>
    </seq>
  </body>
</smil>

Implementing Multi-Path Branching

To implement deeper branching—where answering a question routes the user to entirely different question sets rather than simple feedback:

  • Replace Feedback with Containers: Instead of short feedback media, make the children of <excl> full <seq> containers containing unique lesson modules or remedial questions.
  • Define End Conditions: Use the endsync="first" or endsync="all" attributes on the parent container to control when the quiz transitions to the next module.
  • Skip Logic: Use <a> links targeting future sequential blocks by ID to allow high-performing users to bypass introductory material entirely.
