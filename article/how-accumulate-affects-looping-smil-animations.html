How accumulate Affects Looping SMIL Animations

The accumulate attribute in Synchronized Multimedia Integration Language (SMIL) controls whether a repeating SVG animation resets to its starting value on each iteration or builds progressively upon the value reached at the end of the previous cycle. By modifying this behavior using the values none and sum, developers can create continuous, compounding motion effects—such as objects traveling progressively across a screen or scaling continuously larger—without writing complex keyframes or JavaScript.

The Role of the accumulate Attribute

In SVG SMIL animations defined by elements like <animate>, <animateTransform>, or <animateMotion>, looping is achieved using the repeatCount or repeatDur attributes. When an animation repeats, the browser must decide where the animated property should start on iteration two, three, and beyond. This behavior is governed strictly by accumulate.

The attribute accepts two values:

  • none (default): The animation resets completely at the beginning of each iteration. Every repeat cycle starts from the original from or baseline value.
  • sum: Each repeated iteration builds on the final value of the previous iteration. The ending value of iteration \(N\) becomes the effective baseline for iteration \(N + 1\).

accumulate="none" vs. accumulate="sum"

Consider an SVG circle moving along the X-axis using <animate>:

<circle cx="50" cy="50" r="20" fill="blue">
  <animate 
    attributeName="cx" 
    by="100" 
    dur="2s" 
    repeatCount="3" 
    accumulate="none" />
</circle>

With accumulate="none", the circle starts at cx="50", animates to cx="150" over two seconds, and then abruptly jumps back to cx="50" to repeat the sequence. It does this three times, always traversing the exact same 100-pixel interval.

If you change the attribute to accumulate="sum":

<circle cx="50" cy="50" r="20" fill="blue">
  <animate 
    attributeName="cx" 
    by="100" 
    dur="2s" 
    repeatCount="3" 
    accumulate="sum" />
</circle>

The behavior changes significantly:

  1. Iteration 1: Animates from cx="50" to cx="150".
  2. Iteration 2: Instead of resetting, it treats 150 as the new base, animating from cx="150" to cx="250".
  3. Iteration 3: Continues from 250, animating to cx="350".

Accumulation with Transforms

The accumulate attribute is particularly common in <animateTransform> operations, such as progressive rotations or stepping translations:

<rect width="40" height="40" fill="red">
  <animateTransform 
    attributeName="transform" 
    type="rotate" 
    from="0 20 20" 
    to="45 20 20" 
    dur="1s" 
    repeatCount="4" 
    accumulate="sum" />
</rect>

In this example, the rectangle rotates 45 degrees in the first second, then rotates from 45 to 90 degrees in the second, reaching 180 degrees by the end of the fourth repeat. Without accumulate="sum", the rectangle would snap back to 0 degrees at the start of every second.

Difference Between accumulate and additive

It is easy to confuse accumulate with the additive attribute:

  • additive dictates how an animation combines with the underlying static attribute or other concurrent animations on the same property (e.g., adding an offset to a circle's predefined cx attribute).
  • accumulate applies exclusively across multiple repetitions of the same animation cycle, dictating whether repeated loops compound over time.

For progressive, stair-step, or compounding animations in native SVG without scripting, setting accumulate="sum" is the standard approach.
