SMIL calcMode: Discrete vs Linear vs Paced

The calcMode attribute in SMIL (Synchronized Multimedia Integration Language) controls the interpolation and timing behavior of SVG animations between keyframes. This article explains the functional differences between calcMode="discrete", calcMode="linear", and calcMode="paced", highlighting how each mode handles value progression, transition smoothness, and velocity distribution across animation durations.

Understanding calcMode

When defining an animation using elements like <animate>, <animateTransform>, or <animateMotion>, the browser needs to determine how to advance values over time. The calcMode attribute dictates whether values change instantaneously or continuously, and how speed is distributed between defined points.

calcMode="discrete"

calcMode="discrete" produces instantaneous, step-like changes between values without any continuous interpolation.

  • Behavior: The animation jumps directly from one defined value to the next. The current value remains completely static for its allotted duration until the next keyframe is reached.
  • Timing: When paired with keyTimes, values switch at the designated percentages of total duration. If keyTimes is omitted, the duration is split evenly among the values.
  • Use Cases: Ideal for frame-by-frame sprite animations, toggling visibility, alternating colors abruptly, or switching states without fading or sliding.

calcMode="linear"

calcMode="linear" interpolates continuously between values at an even speed within each individual segment defined by keyframes. This is the default mode for most animated attributes.

  • Behavior: The animation transitions smoothly from point A to point B, then from point B to point C. The rate of change within each segment is constant.
  • Timing: Segments are mapped directly to elapsed time based on the keyTimes list. If segments have different physical distances (e.g., 10px in the first segment and 100px in the second segment) but identical time allocations, the animation will visibly accelerate or decelerate at the segment boundary.
  • Use Cases: Standard, continuous transitions where predictable progress tied directly to specific timestamps is required.

calcMode="paced"

calcMode="paced" forces the animation to proceed at a completely uniform velocity across the entire timeline, regardless of the distance between individual values.

  • Behavior: Instead of relying on predefined segment durations, the browser calculates the total "distance" (numeric or geometric) across all defined values and moves at a single, unchanging rate from start to finish.
  • Timing: The keyTimes attribute is ignored if provided. The browser automatically assigns time to each segment proportionally based on its distance relative to the total distance.
  • Use Cases: Smooth path traversal via <animateMotion> or multi-point position changes where sudden changes in speed at keyframes would look unnatural. Note that paced only works on attributes where a distance or magnitude can be computed (e.g., coordinates, lengths, numbers).
