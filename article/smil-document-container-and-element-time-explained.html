SMIL Document, Container, and Element Time Explained

Synchronized Multimedia Integration Language (SMIL) relies on a hierarchical timing model to coordinate complex multimedia presentations and animations. This article breaks down the functional differences between SMIL document time, container time, and element time, illustrating how the presentation runtime calculates when media items begin, synchronize, and end.

Document Time

Document time represents the global, absolute timeline of the entire SMIL presentation. It begins at zero the exact moment the document starts rendering or playing in the user agent. Every event, element, and container ultimately maps back to this macro-level clock. Document time runs continuously and monotonically, remaining unaffected by local pauses, delays, or loops within specific child elements.

Container Time

Container time is a relative timeline established by a parent time container, such as <par> (parallel), <seq> (sequence), or <excl> (exclusive). A container’s local timeline starts at zero the moment the container itself becomes active within the presentation.

Child elements placed inside a container define their start, end, and duration attributes relative to this container timeline rather than the global document time. For example:

  • In a <seq> container, container time progresses as each child element plays one after another.
  • In a <par> container, multiple child elements share the same container zero-point, playing simultaneously unless assigned an offset relative to that container clock.

If a container pauses or changes its playback rate, the container time for all nested children is affected simultaneously.

Element Time

Element time refers to the internal, local clock of an individual media or animation element. It begins at zero the instant the specific element activates and starts its active duration.

Element time governs how the actual media content is sampled and rendered. It accounts for intrinsic timeline modifications that do not affect the parent container, including:

  • Repetition: Iterating playback with repeatCount or repeatDur resets or loops the element's simple duration while container time marches forward.
  • Speed and Direction: Attributes that accelerate, decelerate, or reverse the playback rate alter the pace of element time relative to container time.
  • Clipping: Attributes such as clipBegin offset the element's internal media clock so playback starts at a specific timestamp within the source file.

Summary of Differences

The primary difference lies in their scope and hierarchy:

  • Document Time is the universal, absolute reference clock for the entire presentation.
  • Container Time is the local reference clock shared by grouped elements within a structural timing block.
  • Element Time is the internal playback clock applied directly to a single media object, reflecting loops, clipping, and rate changes.
