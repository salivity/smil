Digital Signage SMIL Power and Reboot Commands

Digital signage networks rely on Synchronized Multimedia Integration Language (SMIL) to automate media playback, display sleep modes, and scheduled maintenance. This guide provides an overview of the core commands, metadata configurations, and wallclock triggers used in SMIL-compliant appliances to manage hardware power states, control external screens via RS-232/CEC, and synchronize system reboots for continuous operational stability.

Display Power Management in SMIL

Digital signage players running SMIL typically control display panels through internal power-saving states (DPMS), HDMI Consumer Electronics Control (CEC), or serial commands (RS-232).

1. Wallclock Scheduling for Screen States

Players determine when a display should be active by scheduling content blocks using standard SMIL wallclock syntax. When content is not actively scheduled, the player enters standby mode and turns off the display output.

<seq>
  <!-- Screen turns on and plays content between 08:00 and 20:00 daily -->
  <par begin="wallclock(R/2026-01-01T08:00:00/P1D)" dur="12h">
    <video src="playlist.mp4" repeatCount="indefinite" />
  </par>
</seq>

When the active duration (dur="12h") completes, the player ceases video output. In most commercial hardware, loss of the video signal triggers the connected monitor to enter sleep or power-saving mode.

2. Direct Display Control via URI Commands

Many advanced SMIL implementations (such as A-SMIL) support proprietary internal URIs to issue direct power-on and power-off instructions to connected screens via HDMI-CEC or RS-232 interfaces.

  • Power On Display: 
    <ref src="adapi:display/power/on" begin="wallclock(R/2026-01-01T06:00:00/P1D)" />
  • Power Off / Standby Display: 
    <ref src="adapi:display/power/off" begin="wallclock(R/2026-01-01T22:00:00/P1D)" />

3. Global Meta Directives

Power policies can also be defined globally in the <head> section of the SMIL file using player-supported <meta> tags:

<head>
  <!-- Define non-operational sleep periods -->
  <meta name="screen-power-mode" content="auto" />
  <meta name="screen-off-time" content="22:00:00" />
  <meta name="screen-on-time" content="06:00:00" />
</head>

Reboot Synchronization Commands

Regular reboots clear system caches, reset memory, and ensure network stability. SMIL provides both declarative <meta> tags and timed synchronization triggers to execute system-level restarts without interrupting business hours.

1. Scheduled Reboot via Action URIs

You can execute a hard or soft reboot by triggering an appliance API call inside a scheduled parallel (<par>) or sequence (<seq>) block:

<seq>
  <!-- Triggers an automated system reboot every night at 03:00 AM -->
  <ref src="adapi:system/reboot" begin="wallclock(R/2026-01-01T03:00:00/P1D)" />
</seq>

When the wallclock time is reached, the SMIL interpreter passes the execution request directly to the media appliance firmware to initiate a graceful system reboot.

2. Head-Level Maintenance Meta Tags

Certain SMIL media appliances allow administrators to configure daily or weekly reboot cycles globally within the document header:

<head>
  <!-- Executes a synchronized reboot at a predetermined time -->
  <meta name="scheduled-reboot" content="04:00:00" />
  <meta name="reboot-random-delay" content="300" />
</head>

The optional reboot-random-delay attribute (specified in seconds) staggers reboots across a large fleet of displays. This prevents simultaneous network spikes when players reconnect to content servers after restarting.

Best Practices for Synchronization

  • Time Server Sync (NTP): Wallclock commands depend entirely on accurate player clocks. Ensure all SMIL devices synchronize with a Network Time Protocol (NTP) server before applying wallclock reboot or power routines.
  • Separation of Concerns: Keep reboot commands isolated from high-priority emergency broadcast loops so that critical notifications cannot be interrupted by a maintenance cycle.
  • Fallbacks: Combine software display commands (adapi:display/power/off) with player hardware sleep modes so the screen reliably powers down even if a third-party monitor fails to accept an HDMI-CEC command.
