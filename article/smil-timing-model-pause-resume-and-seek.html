SMIL Timing Model: Pause, Resume, and Seek

The Synchronized Multimedia Integration Language (SMIL) timing model defines a structured framework for coordinating concurrent and sequential media elements over time. Programmatic manipulation—specifically pausing, resuming, and seeking—relies on manipulating element-specific and container-level time graphs via standardized DOM interfaces like ElementTimeControl. Understanding how the SMIL engine recalculates active durations, adjusts local clocks, and maintains synchronization relationships provides complete control over dynamic interactive multimedia presentations.

The SMIL Clock Hierarchy

To understand programmatic operations, it is necessary to distinguish between the various clocks within the SMIL runtime:

  • Document Time: The global wall-clock time established when the document begins presentation.
  • Container Time: The time scale established by time container elements (<seq>, <par>, or <excl>).
  • Element Time (Simple and Active Time): The local clock of an individual element, which advances only when the element is actively running.

Programmatic controls alter the relationship between global document time and local element time by inserting time offsets and freezing or shifting the local clock.

Programmatic Pause and Resume

SMIL elements that implement the ElementTimeControl interface expose programmatic control through methods such as pauseElement() and resumeElement().

The Pause Operation

When an element's pauseElement() method is invoked:

  1. Clock Freezing: The element’s active time clock halts at its current position (\(T_{\text{pause}}\)).
  2. State Preservation: The presentation engine preserves the visual and acoustic state of the element at that exact temporal instant.
  3. Syncbase Impact: If child or dependent elements depend on the paused element’s clock (via syncbase values), their local progression also halts, preserving synchronization across the dependency graph. Global document time continues to advance unhindered.

The Resume Operation

When resumeElement() is executed:

  1. Offset Compensation: The engine calculates the duration the element spent in the paused state (\(\Delta t = T_{\text{resume\_doc}} - T_{\text{pause\_doc}}\)).
  2. Instance Time Adjustment: This elapsed duration is added as an internal offset to the element’s active start and end instance times.
  3. Clock Resumption: Local element time resumes advancing from the exact millisecond where it stopped (\(T_{\text{pause}}\)), ensuring that the active duration remains continuous without skipping frames or content.

Programmatic Seeking

Seeking in SMIL entails moving the presentation playback point forward or backward to an arbitrary time point. This can occur globally via the root document time container or locally within specific time containers using methods like setCurrentTime() or through hyperlinking.

Document-Level Seeking

When seeking programmatically on the global document timeline:

  1. Interval Re-evaluation: The SMIL timing engine recalculates the entire time graph from the document start to the target seek time (\(T_{\text{target}}\)).
  2. State Reconstruction:
    • Elements whose active intervals have already elapsed are marked as finished and their end-state actions (such as fill="freeze" or fill="remove") are resolved.
    • Elements whose active intervals encompass \(T_{\text{target}}\) are initialized or fast-forwarded to their corresponding simple time offset.
    • Elements scheduled to begin after \(T_{\text{target}}\) are placed into an inactive, awaiting state.
  3. Event Suppression: Historically, standard SMIL implementations do not fire intermediate timing events (such as multiple beginEvent or endEvent triggers) for elements passed over during a seek, preventing cascading script execution during timeline jumps.

Element-Level Seeking

When seeking within an individual media element or time container:

  • The parent timeline continues uninterrupted while the targeted element’s local time is set to the designated offset.
  • If an element is sought past its defined dur (simple duration), the engine handles repeat iterations (repeatDur, repeatCount) or terminates the element based on its container constraints.

Integration in Modern SVG Implementations

Because standalone SMIL is largely consumed today through SVG animation elements (<animate>, <animateTransform>, etc.), programmatic access is achieved using the SVGAnimationElement DOM interface:

  • element.pauseElement() stops the animation at its current frame.
  • element.unpauseElement() (or resumeElement()) resumes animation flow.
  • svgRootElement.setCurrentTime(seconds) acts as the primary seek mechanism, forcing the SVG engine to recalculate and render all running SMIL animations at the specified timestamp.
